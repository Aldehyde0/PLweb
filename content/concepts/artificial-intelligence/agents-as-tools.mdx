## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
有时专家只需要返回材料，不应接管用户对话；主管还要统一格式、规则和最终判断。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Agents as Tools 让一个 Agent 作为另一个 Agent 的函数工具运行，用于有边界的专业子任务。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
负责人把分析任务交给专家，专家交回报告，但最终由负责人向用户汇报。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
Manager 始终拥有最终回答责任。

子 Agent 输入应收窄为必要任务，输出应有明确契约。

嵌套运行增加延迟与成本，需要追踪父子关系。
:::


## 理解与实践步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 定义专业 Agent
2. 包装为具名工具
3. 主管选择并调用
4. 专家返回结果
5. 主管验证并汇总
:::

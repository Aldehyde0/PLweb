## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
模型、工具、网络、状态和权限都是独立失败源，端到端可靠性通常低于任一局部组件分数。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
可靠性是系统在正常与异常条件下持续满足明确验收标准，并能解释和恢复失败的能力。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
可靠系统不只“通常能做”，还知道什么时候不能做、失败在哪里以及如何安全重试。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
每个边界都使用结构化输入输出契约。

限制步数、时间、成本和副作用。

离线评测、线上追踪和人工反馈形成闭环。
:::


## 数学表达 {#formulas}

::::formula{index="0"}
:::field{path="formulas.0.label" type="text"}
### 串行流程的联合成功概率
:::

:::field{path="formulas.0.expression" type="math"}
$$
P(A\cap B\cap C)=P(A)\,P(B\mid A)\,P(C\mid A\cap B)
$$
:::

:::field{path="formulas.0.description" type="text"}
A、B、C 分别表示规划、执行、验收三个环节达标。公式描述三者同时达标的概率，是条件概率的链式法则，不要求各环节独立。实际任务成功必须另有明确验收标准，不能把模型自报“通过”当作真实成功。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 从同一批任务统计端到端通过率
:::

:::field{path="numericalExample.given" type="list"}
- 以下数字仅为教学假设，不是实测数据。
- 1000 个任务中，950 个规划达标；其中 855 个执行达标；最后 838 个通过验收。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 规划达标比例为 950 / 1000。
2. 在规划达标的任务中，执行达标比例为 855 / 950。
3. 在前两步都达标的任务中，验收达标比例为 838 / 855。
4. 三者相乘，得到 838 / 1000 = 83.8%。
:::

:::field{path="numericalExample.result" type="text"}
这批假设任务的联合通过率为 83.8%，不需要假设三个环节相互独立。
:::

:::field{path="numericalExample.comparison" type="list"}
- 不能直接相乘三个来自不同样本的总体通过率。
- 线上评估还应按任务类型和失败原因分组，检查验收标准是否可靠。
:::

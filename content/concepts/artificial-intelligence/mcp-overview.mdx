## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
每个应用都为每个数据源手写连接器会形成 N×M 集成；协议把发现、调用和内容类型标准化。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
MCP 全称 Model Context Protocol。它规定 Client 与 Server 如何发现和调用能力，不等同于某个具体工具、API 或 Agent。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
MCP 像通用插座规范：Server 提供插口后的工具与资料，Client 负责连接，Agent 决定何时使用；插座本身不替你完成任务。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
MCP Server 可提供 Tool、Resource 与 Prompt；当前官方规范中三者控制方式不同。

Client 管理连接、能力发现、请求与响应，并把允许的能力交给宿主应用。

普通 API 是某服务的业务接口；MCP 在其上提供面向模型/Agent 的统一发现与调用约定。

函数调用定义应用内工具接口；MCP 可从独立 Server 动态提供工具和资源。

Skill 描述工作方法；MCP 描述通信与能力暴露。
:::


## 理解与实践步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 用户任务进入 Agent
2. Agent 查看 Client 暴露的允许能力
3. MCP Client 与 Server 协商并发现能力
4. Agent 选择 Tool 或请求 Resource
5. Client 发送协议请求
6. Server 执行并返回结构化结果
7. Agent 验证结果并继续或完成
:::


## 实际应用 {#applications}

:::field{path="applications" type="list"}
- 本地文件服务
- 远程业务服务
- 统一工具目录
:::


## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 把 MCP 当 Agent
- 默认信任任意 Server
- 暴露全部写工具
- 混淆 Streamable HTTP 中使用 SSE 与旧 HTTP+SSE 传输
:::

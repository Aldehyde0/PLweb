## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
MCP 早期 HTTP+SSE 方案已被 Streamable HTTP 替代，旧教程若不标日期会误导新实现。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
传输规定 Client 与 Server 如何承载协议消息；它不改变 Tool、Resource、Prompt 的语义。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
同一份协议消息可以走本地管道或网络公路，但路线、认证和攻击面不同。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
stdio 由 Client 启动本地 Server 子进程，通过标准输入输出交换消息。

Streamable HTTP 是当前远程标准；2026-07-28 规范进一步转向无状态核心和基于请求的交互。

旧 HTTP+SSE 自 2025-03-26 被 Streamable HTTP 替代，2026-07-28 官方说明其正式弃用并提供一年迁移窗口。

OpenAI Responses API 当前 Remote MCP 文档仍说明兼容 Streamable HTTP 或 HTTP/SSE；新实现应优先 Streamable HTTP，兼容不等于推荐。
:::


## 理解与实践步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 判断本地还是远程
2. 本地优先评估 stdio
3. 远程使用当前 Streamable HTTP
4. 配置认证与来源校验
5. 旧 Server 仅在迁移期兼容
:::

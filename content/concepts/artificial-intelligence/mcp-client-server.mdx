## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
把所有 MCP 能力都叫“工具”会忽略资源读取、用户选择 Prompt 和不同权限模型。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Client 位于宿主应用中并连接 Server；Server 暴露 Tool、Resource 与 Prompt；Tool 执行动作，Resource 提供上下文，Prompt 提供可参数化模板。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
Client 像前台，Server 像服务柜台；Tool 是办理业务，Resource 是可查资料，Prompt 是预制申请模板。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
当前 MCP 规范把 Tools 描述为模型控制、Resources 为应用控制、Prompts 为用户控制的教学性控制层次。

能力发现先于调用，Client 可以过滤 Server 宣告的集合。

Server 宣告能力不等于用户已授权每次调用。
:::


## 理解与实践步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 建立连接与能力协商
2. 列出 tools/resources/prompts
3. 按任务与权限过滤
4. 发出带 id 的请求
5. 接收 result 或 error
6. 把结果交回宿主
:::

## 通俗直觉 {#intuition}

:::field{path="explanation" type="text"}
在迷宫中找出口时，困难不只是知道当前位置，还要决定先试哪条路，并避免在环路里反复绕圈。状态空间搜索把问题变成初始状态、合法动作、后继状态和目标测试，再系统地探索可能路径。

状态必须足以区分后续可行行动。例如带钥匙的迷宫不能只记录位置；同一位置“有钥匙”和“无钥匙”是不同状态，否则去重可能错误地丢掉能够开门的路径。
:::


## 核心原理 {#core-principle}

:::field{path="principle" type="text"}
搜索树中的节点代表一条探索路径到达的状态，状态图则可以有环，也可能有多条路径到同一状态。维护已访问集合能够减少重复扩展，但去重依据必须与问题状态定义一致。

广度优先搜索使用先进先出队列。起点先扩展，再扩展离起点一步的状态，然后是两步的状态；在每条边代价相同的条件下，第一次找到目标时的路径具有最少步数。

深度优先搜索沿一条分支深入，通常不保证最短路径；边代价不同时，需要考虑统一代价搜索等方法，而不能把 BFS 的最少边数误称为最低总成本。若用启发式引导搜索，还要讨论它对最优性的影响。

树状空间的节点数可能随深度指数增长。下方复杂度表达式描述固定分支因子、按层展开树的近似规模，不能代替有限图上按顶点和边数分析开销；保存整条路径也比只保存父节点占用更多内存。
:::


### 案例：逐层找到 A 到 F 的路线

构造一个无权图：A 连接 B、C，B 连接 D，C 连接 E，D 和 E 都连接 F。按 B 先于 C 的邻接顺序，队列先后取出 A、B、C、D、E、F，返回 A → B → D → F。

经 C、E 的路线同样有 3 条边，BFS 并不承诺唯一答案，只承诺该前提下步数最少。若把 B 到 D 的耗时改成 20 分钟、其余边都是 1 分钟，两条路线的边数仍相同，但经 C 的路线更快，此时不能继续用 BFS 证明最低耗时。

## 数学公式 {#formulas}

:::field{path="formula.expression" type="math"}
$$
b^0 + b^1 + … + b^d = O(b^d)
$$
:::

:::field{path="formula.description" type="text"}
b 是分支因子，d 是最浅解深度，说明搜索空间会指数增长。
:::


## 工作流程 {#algorithm-steps}

:::field{path="workflow" type="list"}
- 建立初始状态队列
- 取出最早加入的状态
- 扩展未访问邻居
- 遇到目标后回溯路径
:::


## 代码示例 {#code}

:::field{path="code.language" type="text"}
Python
:::

:::field{path="code.source" type="code" trailing="0"}
```Python
from collections import deque

def bfs(graph, start, goal):
    queue = deque([(start, [start])])
    visited = {start}
    while queue:
        node, path = queue.popleft()
        if node == goal:
            return path
        for nxt in graph.get(node, []):
            if nxt not in visited:
                visited.add(nxt)
                queue.append((nxt, path + [nxt]))
    return None

graph = {
    "A": ["B", "C"], "B": ["D"], "C": ["E"],
    "D": ["F"], "E": ["F"], "F": [],
}
path = bfs(graph, "A", "F")
print(" -> ".join(path) if path else "no path")
print(bfs(graph, "F", "A"))
```
:::

:::field{path="code.highlights" type="list"}
- deque 保证浅层节点先被扩展，visited 防止环路与重复入队。
- 固定邻接顺序使本例选择经 B 的最短路径；等长解可能不唯一。
- 示例同时覆盖成功路径和目标不可达时的返回值。
:::

:::field{path="codeExplanation" type="text"}
完整输入是上方案例的有向无权图。visited 在入队时标记，避免重复入队；graph.get 允许没有显式邻接项的终点，找不到路径时返回 None。

预期输出为两行：第一行 `A -> B -> D -> F`，第二行 `None`。第二次查询从 F 到 A，没有可走的有向边，因此无解。这里把完整路径放在队列中是便于教学的实现，大图通常使用父节点表回溯以减少复制。
:::

## 常见误区 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 把位置当作完整状态，遗漏钥匙、剩余资源等会改变后继动作的信息。
- 出队后才去重而没有防止重复入队，造成大量冗余；有环时完全不去重甚至无法结束。
- 把等权图上的最少步数结论推广到任意带权图，或忽略搜索的内存预算。
:::

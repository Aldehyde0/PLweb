## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
优化器决定怎样把梯度转为参数变化，调度器决定学习率怎样随训练推进。二者职责不同，更新频率不一致会使实际训练配方偏离记录。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
优化器保存参数引用及更新状态；学习率调度器修改优化器参数组中的学习率。调度轴可以是 epoch、参数更新数或验证指标，必须按具体调度器约定使用。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
优化器决定怎么迈步，调度器决定今天迈多大步；数了多少批数据并不总等于迈了多少次步。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
SGD 使用当前梯度或带动量的历史方向，AdamW 使用每参数矩估计并可施加解耦衰减。建立优化器后新增或解冻参数，不会凭空让它们进入旧参数组，必须检查实际优化参数集合。

调度器通常在 optimizer.step 后推进；StepLR 常按 epoch，OneCycleLR 常按更新，ReduceLROnPlateau 接收验证指标。调用次数是数学计划的一部分，不是随意放在哪里都一样。

多个参数组可以有不同初始学习率，但恢复训练时需要同时恢复优化器和调度器状态。若重新创建调度器却从旧 epoch 接着记日志，打印的轮次并不能保证学习率轨迹接上。
:::

### 把 SGD 更新与 StepLR 顺序对齐

代码在更新前读取 used_lr，更新后才调用 scheduler.step，因而日志明确区分“这一步用的学习率”与“下一步的学习率”。

若在每个微批都推进，而两微批才优化一次，计划就被加速两倍。遇到 AMP 因非有限梯度跳过更新时，同样要考虑是否推进按更新计数的计划。

### 把 SGD 更新与 StepLR 顺序对齐的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}

:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对把 SGD 更新与 StepLR 顺序对齐，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
p = torch.nn.Parameter(torch.tensor(1.))
opt = torch.optim.SGD([p], lr=0.1)
sched = torch.optim.lr_scheduler.StepLR(opt, step_size=1, gamma=0.5)
for step in range(1, 4):
    opt.zero_grad(set_to_none=True)
    p.grad = torch.ones_like(p)
    used = opt.param_groups[0]["lr"]
    opt.step()
    sched.step()
    print(f"step={step} used_lr={used:.3f} parameter={p.item():.3f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 显式构造常量梯度以隔离调度效果。
- 每行记录的是本次更新使用的学习率。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
step=1 used_lr=0.100 parameter=0.900
step=2 used_lr=0.050 parameter=0.850
step=3 used_lr=0.025 parameter=0.825
```

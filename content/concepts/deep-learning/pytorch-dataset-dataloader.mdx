## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
模型期望一批规整张量，而原始数据可能分散在文件或记录中。Dataset 负责单样本读取，DataLoader 负责采样和组批，分清两者有助于定位数据错误与性能瓶颈。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Dataset 定义可索引样本的读取契约；DataLoader 根据采样器、批大小和 collate_fn 将多个样本组织成批，并可通过工作进程并行读取。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
Dataset 像按编号取货的仓库，DataLoader 像决定取哪些货、每箱装多少以及怎样打包的装箱员。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
常见 map-style Dataset 实现 __len__ 和 __getitem__，每次返回特征与目标。默认 collate 会把同形状 Tensor 堆叠并添加 batch 维，因此单样本输出 shape 决定批量接口。

shuffle 改变采样顺序，不应改变标签对应关系。训练常打乱，验证通常固定顺序；变长序列需要自定义 collate_fn 做 padding 并返回长度或 mask，而不是期待默认堆叠自动处理。

num_workers 决定数据读取进程数，不直接控制模型计算并行。Windows 多进程脚本需要 main 保护，初步调试可先用 0，让读取异常在主进程清楚暴露。读取加速也不能掩盖训练验证泄漏。
:::

### 五条样本如何组为三批

即使最后只有一条，特征 shape 仍是 (1,2)，不是 (2,)。这使模型能用相同批量接口处理尾批，也说明无参数 squeeze 可能破坏契约。

示例使用顺序采样以便核对，不代表训练必须禁用 shuffle。真实项目还应检查样本 ID，确保增强、读取和标签始终配对。

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
from torch.utils.data import TensorDataset, DataLoader
x = torch.arange(10, dtype=torch.float32).reshape(5, 2)
y = torch.tensor([0, 1, 0, 1, 0])
loader = DataLoader(TensorDataset(x, y), batch_size=2, shuffle=False, num_workers=0)
for i, (xb, yb) in enumerate(loader, 1):
    print(f"batch={i} x={tuple(xb.shape)} y={tuple(yb.shape)} labels={yb.tolist()}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 数据、Dataset 与 DataLoader 完整定义。
- num_workers=0 可跨平台直接运行。
:::

```text
batch=3 x=(1, 2) y=(1,) labels=[0]
```

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 变长序列为什么默认 collate 会失败？
:::

:::field{path="commonQuestions.0.answer" type="text"}
默认堆叠要求同一批对应张量形状一致。应通过 collate_fn 补齐长度并返回 mask，或采用其他明确的变长处理。
:::

:::

:::field{path="commonQuestions.1.answer" type="text"}
DataLoader 只组织数据，不会自动保证分割独立、标签正确或预处理无泄漏。

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
浮点精度会影响显存、吞吐和数值范围。AMP 根据算子选择适合的精度，而不是简单把模型和所有输入一律转成半精度。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
自动混合精度由 autocast 按设备和算子选择 dtype；float16 训练常配合 GradScaler 对损失缩放，降低小梯度下溢风险。bfloat16 的指数范围不同，通常不需要同样的缩放策略。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
不同工序使用不同精度的量尺：大矩阵乘法可用更便宜的尺，敏感累加与损失计算保留更稳的精度。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
autocast 通常包住前向和损失，不包住整个优化器逻辑。模型参数往往仍保留 float32 主副本；实际算子是否降精度由支持策略决定，不能从上下文名称推断每个输出 dtype。

GradScaler 先将损失乘缩放因子，再反向；在更新前还原梯度，检测非有限值并按需跳过更新、调整缩放。若需要裁剪，必须先 unscale，再按原梯度尺度裁剪。

CUDA float16、CPU bfloat16 的支持和加速效果不同。CPU 示例可以明确关闭 AMP，验证同一训练路径的回退；它不能证明 GPU 加速，也不能在没有 CUDA 的机器上伪造吞吐数字。
:::

### CPU 上验证 AMP 关闭后的完整训练步

示例故意不启用不受当前硬件支持的 CUDA 算子。实际切换到 CUDA 时，应把模型与输入迁到同一设备，再按 float16 或 bfloat16 配方启用 autocast 与缩放。

衡量 AMP 应在相同任务预算下同时观察数值稳定性、显存和耗时。单次小矩阵计算的快慢无法代表大网络吞吐，也不能把训练能运行当成精度没有影响。

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
from torch import nn
model = nn.Linear(1, 1, bias=False)
with torch.no_grad():
    model.weight.fill_(1.)
opt = torch.optim.SGD(model.parameters(), lr=0.1)
scaler = torch.amp.GradScaler("cpu", enabled=False)
opt.zero_grad(set_to_none=True)
with torch.amp.autocast("cpu", enabled=False):
    loss = (model(torch.tensor([[2.]])) - 6).square().mean()
scaler.scale(loss).backward()
scaler.step(opt)
scaler.update()
print(f"dtype={model.weight.dtype} loss={loss.item():.1f} weight={model.weight.item():.1f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}

- 明确关闭 AMP，不把普通精度结果称为混合精度效果。
:::

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### AMP 时可以先裁剪再 unscale 吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
不应这样做。梯度仍乘着动态缩放因子，裁剪阈值就不再对应真实梯度尺度，应先 scaler.unscale_(optimizer)。
:::

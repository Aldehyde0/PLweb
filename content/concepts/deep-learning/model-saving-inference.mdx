## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
一个可用模型不仅是权重文件，还包含结构、输入加工和类别解释。加载后能得到某个张量，不代表它与训练时具有相同含义。
:::

:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
权重像一组零件参数，配置是装配图，预处理和类别表则是使用说明，缺少任一项都可能装出不同系统。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
通常保存 state_dict 而非依赖完整 Python 对象序列化，恢复时先创建同一结构再 load_state_dict。state_dict 包含参数和持久 buffer，但不包含 forward 代码、词表或业务阈值。

推理前同时调用 eval 与 inference_mode：前者改变 Dropout、BatchNorm 等行为，后者关闭自动微分开销。map_location 可把原 GPU 权重加载到 CPU，输入与模型仍需在兼容设备和 dtype 上。

weights_only=True 适合限制加载内容，仍应只加载可信来源。结构键匹配不代表输入通道顺序和标签表正确；交付前应比较固定输入的输出并检查输出类别解释。
:::

### 在内存保存并恢复固定线性模型

示例使用内存缓冲区，避免留下演示文件。真实文件保存可使用同样的资产内容，但还应记录版本和预处理，例如输入是否已标准化。

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 在内存保存并恢复固定线性模型的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}

:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对在内存保存并恢复固定线性模型，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import io
import torch
from torch import nn
model = nn.Linear(2, 1)
with torch.no_grad():
    model.weight.copy_(torch.tensor([[2., -1.]]))
    model.bias.fill_(0.5)
model.eval()
x = torch.tensor([[3., 4.]])
buffer = io.BytesIO()
torch.save({"in_features": 2, "state": model.state_dict(), "labels": ["score"]}, buffer)
buffer.seek(0)
artifact = torch.load(buffer, map_location="cpu", weights_only=True)
restored = nn.Linear(artifact["in_features"], 1)
restored.load_state_dict(artifact["state"])
restored.eval()
with torch.inference_mode():
    a, b = model(x), restored(x)
print(f"prediction={b.item():.1f} max_diff={(a - b).abs().max().item():.1f}")
print(artifact["labels"])
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 保存配置与标签，不只保存参数。
- 使用 weights_only 和 CPU 映射并实际加载核对。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
prediction=2.5 max_diff=0.0
['score']
```
:::

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 为什么 eval 和 inference_mode 都需要？
:::

:::field{path="commonQuestions.0.answer" type="text"}
eval 控制模块训练行为，inference_mode 控制自动微分；只用其中一个不能同时完成两项职责。
:::

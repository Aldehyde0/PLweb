## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
序列模型需要让远处位置直接交换信息，又要能在训练中并行处理位置。Transformer 用注意力实现位置通信，再用逐位置前馈层变换特征。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Transformer 由注意力、逐位置前馈网络、残差、归一化和位置信息组成。Encoder、因果 Decoder 与 Encoder-Decoder 的可见范围和任务接口不同。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
注意力负责把各位置需要的上下文取来，前馈层负责消化每个位置的新表示；残差路径让已有表示能够保留。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
自注意力令同一序列提供 Q、K、V，交叉注意力则由一侧提供 query、另一侧提供 key/value。Encoder 通常能看全部输入，生成式 Decoder 使用因果约束，避免训练时读取未来 token。

FFN 独立应用于每个位置，常先把 D 维扩到较大隐藏维，再投回 D。残差要求子层输出维度对齐，LayerNorm 放置位置形成 Pre-LN 或 Post-LN 配方；这些结构不能只用“有注意力”概括。

标准稠密全局注意力的分数数目随长度平方增长，计算还受特征维度影响；长上下文会显著增加内存。没有任何位置信息的自注意力本身不能区分一般的排列顺序。框架 EncoderLayer 也不会自动替你添加位置编码。
:::

### 一个 Encoder 层保持序列长度与表示维度

本例位置项仅用位置编号除以 10，目的是显式提醒位置来源，不是推荐替代成熟正弦、学习式或旋转位置方案。nn.TransformerEncoderLayer 接收的已经是隐藏表示，Embedding 与位置处理在外部完成。

若任务是整句分类，还需添加带 mask 的池化或特定分类 token；若是语言建模，还需因果 mask、目标移位和词表输出头。一个层的前向形状正确不等于完整任务已经建好。

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对一个 Encoder 层保持序列长度与表示维度，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
from torch import nn
torch.manual_seed(7)
layer = nn.TransformerEncoderLayer(8, 2, dim_feedforward=16, dropout=0., batch_first=True, norm_first=True)
layer.eval()
x = torch.zeros(2, 4, 8)
demo_position = torch.arange(4, dtype=torch.float32)[None, :, None] / 10
with torch.inference_mode():
    y = layer(x + demo_position)
print("input:", tuple(x.shape), "output:", tuple(y.shape))
print("finite:", bool(torch.isfinite(y).all()))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 显式添加演示位置项，模块不会自动生成位置。
- 只检查一层结构，不虚构端到端任务结果。
:::

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### Transformer 不加位置表示能知道词序吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
一般自注意力只根据内容混合，缺少区分排列的充分位置信息；因果可见性有部分顺序约束，但通常仍需按架构配方提供位置机制。
:::

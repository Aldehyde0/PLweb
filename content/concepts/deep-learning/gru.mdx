## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
LSTM 的多组门和两种状态增加了复杂度。GRU 将记忆控制压缩到单一隐藏状态，并用更新门与重置门调节历史和候选内容的结合。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
GRU 以重置门影响候选状态，以更新门混合旧状态与新候选。这里采用 PyTorch 约定：h=(1-z)×n+z×h_prev，因此 z 越大越保留旧状态。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
更新门像混合旋钮，在旧笔记和新建议之间分配比例；重置门决定构造新建议时要参考多少旧笔记。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
重置门 r 与更新门 z 都依赖输入及前一状态。候选 n 使用 tanh，随后做逐元素混合。不同教材可能把更新门 z 的命名互补，比较公式时必须看它乘的是旧状态还是候选状态。

PyTorch 在候选分支采用重置门乘在隐藏线性变换结果上的实现，和某些原始公式把 r 先乘 h 再做矩阵变换不完全相同。迁移手写权重时，不能只按三个门的名字机械复制。

GRU 没有独立 c 状态，同 hidden size 下通常比 LSTM 参数少，但不保证在每种任务更快或更准确。长序列、padding、初始状态和跨样本重置仍与其他循环模型一样需要处理。
:::

### 更新门如何控制旧状态保留

这是给定门值的代数演示，不要求完整 GRU 先计算门。它能防止一个常见误读：看到“更新门大”就断言更新更多新信息，却没有检查公式约定。

z=1 时完全保留旧状态，z=0 时完全使用候选。候选本身已经通过重置门参考历史，所以“选择候选”也不等于完全忘记过去。

### 更新门如何控制旧状态保留的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对更新门如何控制旧状态保留，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
h_prev, candidate = torch.tensor(2.), torch.tensor(0.5)
for z in [0.2, 0.8]:
    h = (1 - z) * candidate + z * h_prev
    print(f"z={z:.1f} hidden={h.item():.1f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 采用页面与 PyTorch 相同的旧状态系数约定。
- 只验证混合公式，不引入未训练的网络表现。
:::

```text
z=0.2 hidden=0.8
z=0.8 hidden=1.7
```

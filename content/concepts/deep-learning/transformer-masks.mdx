## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
语言生成训练时整段文本已在内存中，若不屏蔽未来，模型可以偷看答案。padding 又会让无意义位置参与归一化，因此需要两种不同的可见性约束。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
因果 mask 限制 query 只读取当前及过去 key；padding mask 排除无效 key。mask 在 softmax 前修改分数，训练生成模型还需要输入与目标的正确移位。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
因果 mask 是不许翻后页，padding mask 是空白页不算内容；这两条规则解决不同问题。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
加性 mask 对允许位置加 0，对禁止位置加负无穷，使其 softmax 权重为零。布尔 mask 则依 API 解释。nn.MultiheadAttention 的 True 常表示禁止，而函数式 scaled_dot_product_attention 的布尔 True 表示允许，不能直接复用同一方向。

key_padding_mask 常为 $[N,L_k]$，因果 attn_mask 常为 $[L_q,L_k]$ 或约定的批头形状。屏蔽 key 并不保证 padding query 的输出为零；后续池化、损失和指标仍需有效位置处理。

若一整行所有 key 都被屏蔽，softmax 可能产生非有限值，行为还取决于具体实现。应避免全空样本或定义明确策略。目标右移也不能由 mask 替代，否则训练标签仍可能与输入错位。
:::

### 三位置因果注意力的均匀权重

这个例子直接在分数矩阵上演示屏蔽顺序。如果先 softmax 再把未来权重置零，第二行剩余权重会只有 2/3 而非 1，已经不是同一注意力分布。

代码的 blocked=True 明确表示禁止，因为它被用于 masked_fill；传给其他 API 前仍要按文档转换，不能从变量 dtype 推断方向。

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 三位置因果注意力的均匀权重的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对三位置因果注意力的均匀权重，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
scores = torch.zeros(3, 3)
blocked = torch.triu(torch.ones(3, 3, dtype=torch.bool), diagonal=1)
weights = scores.masked_fill(blocked, float("-inf")).softmax(-1)
for row in weights.tolist():
    print([round(v, 6) for v in row])
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 屏蔽发生在 softmax 之前。
- 每行至少一个允许位置，避免全屏蔽行。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
[1.0, 0.0, 0.0]
[0.5, 0.5, 0.0]
[0.333333, 0.333333, 0.333333]
```

### 因果 mask 能替代语言模型目标右移吗？

:::field{path="commonQuestions.0.answer" type="text"}
不能。mask 控制读取范围，移位定义某位置预测哪个下一 token；两者都正确才能避免偷看或目标错位。

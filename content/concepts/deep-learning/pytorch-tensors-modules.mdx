## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
把权重放进普通 Python 列表并不能保证优化器发现它们。要让参数、设备移动和保存加载协同工作，模型需要遵守 PyTorch 的模块注册规则。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Tensor 保存数值与可选的梯度信息；nn.Module 组织计算、子模块、Parameter 和 buffer。Parameter 默认可训练，持久 buffer 保存随模型移动的状态。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
Module 像一份可遍历的设备清单：参数列入优化名单，buffer 列入状态名单，普通属性则不会自动获得同样待遇。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
将 nn.Linear 等子模块赋给 self 的属性，会注册其参数；将 nn.Parameter 赋为属性也会注册。若要装多个层，应使用 ModuleList 或 Sequential，而非期待普通列表自动注册。forward 描述计算，通常通过 model(x) 调用以保留钩子等框架行为。

register_buffer 适合均值、位置表等非训练状态。持久 buffer 会进入 state_dict，并随 .to(device) 移动；普通 Tensor 属性默认不会。requires_grad=False 的参数仍是参数，只是暂停求梯度。

state_dict 保存注册的参数与持久 buffer，不保存 Python 类定义或完整预处理流程。恢复时仍需同一结构及一致配置；即使键名匹配，类别映射错位也会使输出含义出错。
:::

:::field{path="numericalExample.result" type="text"}

:::

### 案例推演与判断

这个模块只有一个可训练标量，offset 虽然参与前向，却不会出现在 parameters() 中。这样可以表达“固定中心化基准，但学习缩放”的语义。

如果把 offset 直接写成普通张量属性，本例在 CPU 上仍能运行，却可能在搬到 GPU 后出现设备不一致。模型能前向运行，并不足以证明状态管理正确。

## 代码实现 {#code}

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 用一个参数和一个 buffer 做线性映射的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对用一个参数和一个 buffer 做线性映射，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
from torch import nn
class Scale(nn.Module):
    def __init__(self):
        super().__init__()
        self.scale = nn.Parameter(torch.tensor(2.))
        self.register_buffer("offset", torch.tensor(1.))
    def forward(self, x):
        return x * self.scale + self.offset
model = Scale()
print(model(torch.tensor([3., 4.])).tolist())
print(list(dict(model.named_parameters())))
print(list(model.state_dict()))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 类定义、输入和导入完整。
- 清单输出直接区分参数与持久 buffer。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
[7.0, 9.0]
['scale']
['scale', 'offset']
```

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 普通列表为什么不适合存放待训练层？
:::

:::field{path="commonQuestions.0.answer" type="text"}
普通列表里的层不会通过列表容器自动注册，模块遍历、设备移动和优化器构建可能遗漏它们；应使用 ModuleList。

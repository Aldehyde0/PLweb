## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
当正类很少时，永远预测负类也可能得到很高准确率。深度学习评估需要从业务代价、类别分布和决策阈值出发，而非只记录一个总准确率。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
类别不平衡评估结合混淆矩阵、每类精确率召回率、F1 或 PR 曲线等指标；训练时的重采样或加权与评估时真实分布应分别处理。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
模型找到多少真正的异常，以及它报警时有多少是真的，是两个不同问题，分别对应召回率与精确率。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
TP、FP、FN、TN 应跨完整评估数据累计，再计算指标。直接平均各批 F1 通常不等于全数据 F1，特别是尾批大小不同或某批没有正例时。多分类还需明确 macro、micro 和 weighted 平均。

阈值控制精确率与召回率的权衡，应按验证集和业务代价选择。使用加权损失或重采样后，输出概率的校准也可能改变，不能默认 0.5 永远合适；最终测试只使用已经锁定的规则。

序列与分割任务需排除 padding 和 ignore 标签。评估分布应尽量代表部署环境，不能为让分数好看把测试集平衡化后仍声称是原分布表现。
:::

### 六条预测手算精确率与召回率

同样的准确率可由不同错误结构产生。若漏掉一个正例代价远高于一次误报，就不能仅凭准确率挑模型，而要检查召回率与误报预算。

代码对分母为零显式返回 0，这是本例约定。真实报告应声明无正预测或无正例时的处理方式，并同时报告类别支持数，避免一个指标掩盖样本过少。

### 六条预测手算精确率与召回率的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}

:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对六条预测手算精确率与召回率，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
y = torch.tensor([1, 1, 0, 0, 0, 0])
pred = torch.tensor([1, 0, 1, 0, 0, 0])
tp = int(((pred == 1) & (y == 1)).sum())
fp = int(((pred == 1) & (y == 0)).sum())
fn = int(((pred == 0) & (y == 1)).sum())
precision = tp / (tp + fp) if tp + fp else 0.
recall = tp / (tp + fn) if tp + fn else 0.
f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0.
print(f"TP={tp} FP={fp} FN={fn}")
print(f"accuracy={(pred == y).float().mean().item():.4f} precision={precision:.4f} recall={recall:.4f} F1={f1:.4f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 全量累计后计算指标。
- 显式处理零分母，未依赖默认行为。
:::

accuracy=0.6667 precision=0.5000 recall=0.5000 F1=0.5000

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 为什么不能平均每个 batch 的 F1？
:::

:::field{path="commonQuestions.0.answer" type="text"}
F1 是计数的非线性比值，各批分数平均会丢失支持数信息；应先汇总混淆计数，再按统一定义计算。
:::

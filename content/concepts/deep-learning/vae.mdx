## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
普通自编码器的潜在空间可能零散、不适合随机采样。VAE 把编码结果变成分布，再用先验约束形成更可采样的空间，同时保留输入重构能力。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
变分自编码器用近似后验 q(z|x) 编码输入，常输出高斯均值 mu 和 logvar，通过重参数化采样，再优化重构项与相对先验的 KL 项。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
编码器给出的不是一个坐标，而是坐标附近的一团概率云；KL 约束让这些云与规定的公共坐标分布保持联系。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
对角高斯后验可写为 z=mu+exp(0.5×logvar)×epsilon，epsilon 来自标准正态。随机性来自与参数无关的 epsilon，因此梯度仍可通过 mu 和 logvar 传回编码器。直接从由参数定义的分布抽样后当常量使用会失去这种路径。

标准正态先验下，单样本 KL 为 -0.5×sum(1+logvar−mu²−exp(logvar))。应先明确按 latent 维求和、按 batch 如何归一化；重构项若按像素平均或求和，都会改变它与 KL 的相对尺度。

重构概率模型取决于数据，例如连续值与二元像素需要不同观测假设。KL 太强可能让后验忽略输入，太弱则先验采样质量不佳；beta 只是权衡参数，不能在不说明归一化时跨实现照搬。
:::

### 两维高斯后验的 KL 与重参数化

固定 epsilon 只是把随机抽样的一次条件写清楚，不代表训练时始终使用它。真正训练需要不断采样，或按明确推断策略使用后验均值。

若把两维重构误差改为均值，重构项会从 2 变成 1，相同 beta 下相对 KL 权重翻倍。因此报告一个 VAE loss 前必须交代求和与平均轴。

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 两维高斯后验的 KL 与重参数化的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对两维高斯后验的 KL 与重参数化，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
mu = torch.tensor([[1., 0.]], requires_grad=True)
logvar = torch.zeros_like(mu)
epsilon = torch.tensor([[0.5, -1.]])
z = mu + torch.exp(0.5 * logvar) * epsilon
kl = -0.5 * (1 + logvar - mu.square() - logvar.exp()).sum(-1).mean()
x, reconstruction = torch.tensor([[0., 2.]]), torch.tensor([[1., 1.]])
recon = (reconstruction - x).square().sum(-1).mean()
print("z:", z.detach().tolist())
print(f"reconstruction={recon.item():.1f} KL={kl.item():.1f} total={(recon + kl).item():.1f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- epsilon 明确给定，确保数值可手算。
- 重构与 KL 都先按特征求和，再按 batch 平均。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
z: [[1.5, -1.0]]
reconstruction=2.0 KL=0.5 total=2.5
```
:::

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 为什么编码器常输出 logvar 而不是方差？
:::

:::field{path="commonQuestions.0.answer" type="text"}
logvar 可取任意实数，经指数得到正方差，便于网络参数化；仍需检查过大指数引起的数值溢出。
:::

:::field{path="commonQuestions.1.question" type="text"}

:::

:::field{path="commonQuestions.1.answer" type="text"}

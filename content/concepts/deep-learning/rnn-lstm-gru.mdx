## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
RNN、LSTM、GRU 都能逐步处理序列，差异主要在状态与门控机制。选型需要结合上下文长度、在线延迟和验证结果，而不是只记一个优劣排名。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
普通 RNN 用单一非线性状态更新，GRU 用两个主要门和单状态，LSTM 用多门及 h、c 双状态。三者都在时间维共享参数。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
三种方法都维护笔记，区别在于笔记的结构和擦写控制，而不是只有某一种才具有历史依赖。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
普通 RNN 计算最简，但长路径梯度容易衰减或放大；LSTM 通过细胞状态加法路径控制记忆；GRU 把旧状态与候选直接混合。门控增加参数，可能改善长期依赖，却同时增加运算与调参成本。

对 batch_first 输入 $[N,L,D]$，单向 output 为 $[N,L,H]$。h_n 为 $[layers×directions,N,H]$，LSTM 还返回同类形状的 c_n。双向网络的输出末维是 2H，但它需要未来上下文，不适合直接用于严格在线因果预测。

比较时应控制数据划分和训练预算，并记录参数量、耗时及任务指标。同 hidden size 的模型参数量不相同，不能把这种比较误说成完全等容量比较。
:::

### 同输入维度与隐藏维度的参数账本

PyTorch 为输入和隐藏线性变换分别设置偏置，因此有 2H 个偏置，而非只算 H。门数的差异直接乘到这套账本上。

相同输出 shape 便于替换模块，却不意味着优化行为相同。若需要公平资源比较，可以进一步调整 H 使参数或推理延迟接近，再用同样验证协议比较。

### 同输入维度与隐藏维度的参数账本的最小验证

:::field{path="codeExamples.0.language" type="text"}

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对同输入维度与隐藏维度的参数账本，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
import torch
from torch import nn
x = torch.zeros(2, 5, 3)
for cls in [nn.RNN, nn.GRU, nn.LSTM]:
    model = cls(3, 4, batch_first=True)
    out, state = model(x)
    params = sum(p.numel() for p in model.parameters())
    print(f"{cls.__name__}: output={tuple(out.shape)} parameters={params}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 相同 D、H、层数与方向进行结构比较。
- 只比较参数与接口，不推断准确率。
:::

```text
LSTM: output=(2, 5, 4) parameters=144
```

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### batch_first 会改变 h_n 的维度顺序吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
不会，它只改变输入和 output 的 batch/time 排列；h_n 的首轴仍组合层数与方向。
:::

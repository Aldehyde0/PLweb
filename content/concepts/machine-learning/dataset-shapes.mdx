## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
机器学习代码中的许多问题来自“数字对了，轴的含义错了”。同样有 12 个元素，一个 3×4 矩阵与一个 4×3 矩阵可以分别表示三条四特征样本与四条三特征样本，不能因为元素数相等就互换。

先标记每个轴的语义，再讨论切片、拼接与模型接口，通常比等到模型报错后猜测 reshape 更可靠。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
常见表格任务把特征写成 X，形状为 (n,d)：n 行样本，d 列特征。单目标 y 通常形状为 (n,)，也存在多输出目标 (n,k)，应按具体估计器约定处理。

样本位置必须在 X、y、时间与实体编号之间保持一致。shape 相同只能说明维度兼容，不能证明同一行仍对应同一个对象。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
把 X 的一行看成一张记录卡，把 y 的相同行看成这张卡的答案。只打乱卡片、不打乱答案，模型仍可能正常 fit，却已经在学习错误配对。
:::

### 用同一 mask 同时筛选 X 与 y

三条样本分别是 [年龄20,收入3]、[年龄40,收入8]、[年龄30,收入5]，标签依次为 [0,1,0]。若筛选收入至少为 5 的记录，mask 应为 [False,True,True]，得到的标签必须是 [1,0]。

若错误地直接取 y 的前两项，会得到 [0,1]：结果长度仍是 2，却已与样本错配。这个例子说明 shape 检查和记录对齐检查缺一不可。


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
筛选、重排与划分应共享同一个行索引或布尔 mask。特征列变化则需要同步更新列名、顺序和后续变换；不要把行操作与列操作混在一起。

单条预测通常仍要保留二维输入，例如两个特征的一条样本是 (1,2)，不是含义不明的长度 2 向量。有些接口会把一维数组解释成不同对象，因此不能只靠自动推断。

转置、reshape 与广播解决不同问题。转置交换轴，reshape 改变分组方式而不保证语义正确，广播按尺寸规则对齐运算；任何一种操作都不能自动修复标签错位。

检查不应止于打印 shape。还要抽查几条样本的标识与标签、各列单位、缺失值和 dtype，确认接口输入与实际数据定义一致。
:::

任何筛选、打乱和划分都必须对 X 与 y 使用相同索引；单条预测也通常保留二维形状 (1,d)。
:::

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 打印 X/y shape
2. 验证第一维相等
3. 随机检查样本标签对应
4. 划分时同时传入 X/y
5. 预测单条时保留二维
:::

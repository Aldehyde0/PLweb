## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
缩放、填补和降维虽然常被叫作预处理，但它们也会从数据学习统计量。若先在全部开发数据上完成这些步骤，再交叉验证模型，验证折已参与塑造训练输入。

Pipeline 把有状态变换与估计器组成同一个可克隆训练流程，让交叉验证能在每个训练折重新拟合全部步骤。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
先对完整 X fit 变换再 cross\_val\_score 会让验证折影响变换状态。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
每一折都要从原始训练材料独立准备笔记，不能共享全班统计。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
fit 阶段按顺序拟合变换并传递结果，最后训练估计器；predict 阶段只使用已经学到的变换。验证折不能重新 fit 填补器或缩放器，否则训练与推理语义不一致。

交叉验证克隆整个 Pipeline，各折保存独立中位数、均值、主成分与模型参数。监督特征选择、目标编码等依赖 y 的步骤更要放在正确边界内；具体编码器还可能需要内部交叉拟合以避免训练行自泄漏。

Pipeline 管理步骤边界，不代替数据划分与特征可用性设计。跨折重复实体、未来字段和错误标签即使都包进 Pipeline 也依然存在。提前缓存的全数据特征也不能因外面再套一层 Pipeline 就被修复。

过采样等改变样本数量的操作只能作用于训练折，需要使用支持采样步骤的合适流程，而不是让验证折也被采样。最终部署应保存整个已拟合预处理与模型，避免训练预测使用不同统计量。
:::

### 案例：检查每折缩放器看过多少行

Iris 的 150 行做 3 折，每折训练 100 行。下方将填补、标准化、PCA 与逻辑回归串起来，返回每折模型后检查 StandardScaler 的 n_samples_seen_ 都是 100。

PCA 也只在该折训练输入中学习，再把验证行投影到对应空间。这个计数检查能揭示把全数据缩放器偷偷放到流程外的问题，却不能证明特征在预测时点可用，因此还需要单独的数据审计。

:::field{path="codeExamples.0.purpose" type="text"}
完整拟合 3 折 Pipeline，并读取每折变换器的状态验证边界。

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
from sklearn.datasets import load_iris
from sklearn.decomposition import PCA
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_iris(return_X_y=True)
pipeline = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
    ("pca", PCA(n_components=2, svd_solver="full")),
    ("model", LogisticRegression(max_iter=1000)),
])
cv = StratifiedKFold(3, shuffle=True, random_state=42)
result = cross_validate(pipeline, X, y, cv=cv, return_estimator=True)
seen = [int(model.named_steps["scale"].n_samples_seen_) for model in result["estimator"]]
assert seen == [100, 100, 100]
print("scaler_training_rows:", seen)
print("pca_components:", [model.named_steps["pca"].n_components_ for model in result["estimator"]])
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 每个缩放器只看 100 行训练数据，未看完整 150 行。
- PCA 的 2 个主成分分别由各折训练数据确定。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
本地 scikit-learn 1.8.0 的核对输出：

```text
scaler_training_rows: [100, 100, 100]
pca_components: [2, 2, 2]
```

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 先调用全数据 fit_transform，再将已变换矩阵送进 Pipeline 或 CV。
- 在验证折重新拟合变换，或让重采样改变验证样本分布。
- 认为 Pipeline 能自动解决实体重复、未来字段和所有目标编码泄漏。
:::

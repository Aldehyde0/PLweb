## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
真实表格常混合数值与类别列，既需要不同的预处理，也需要让这些处理在每个训练折中正确拟合。只把几行变换代码按顺序写好，不一定能保证验证边界。

Pipeline 与 ColumnTransformer 分别解决顺序组合和按列分流，使输入契约、已学状态和模型选择更容易保持一致。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
Pipeline 将多步变换与最终估计器串联；ColumnTransformer 将不同列交给不同变换器，再按约定合并输出。前者主要组织步骤依赖，后者主要组织列类型与分支。

它们不仅是代码简写，也让 fit、transform、参数搜索与持久化可以围绕完整流程工作。但错误的特征定义或时间泄漏，不会因为套了管线就自动消失。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
把原始表分到数值与类别两条加工线，再把统一表示送入分类器。每条加工线保留自己的训练状态，未来表格走同样的路径，而不是临时重新发明编码规则。
:::

### 两列数值、一列类别会变成几列

假设训练表有 age、income 两列数值和 city 一列类别，城市只见过 A、B。两列缩放值加两列 One-Hot，总共形成四个模型输入，而不是仍然三列。

未来城市 C 使用忽略未知值规则时，城市的两列均为 0，但数值分支仍按训练统计量处理。必须检查这是否符合业务，而不能因为输出维度没有变就断言新城市已经被充分验证。


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
数值分支可先填补再缩放，类别分支可先处理缺失再编码。步骤顺序有含义，例如先缩放含缺失数据与先填补后缩放可能不是同一过程。

在交叉验证和参数搜索中传入完整管线，才能让每折独立拟合需要学习的步骤。内部参数通常用步骤名与双下划线定位，搜索空间也应对应这些实际对象。

列名、顺序、未知类别与输出稀疏性属于接口。最好保留原始列名与 get_feature_names_out 等核对信息，防止拼接后的特征与解释脱节。

保存完整管线有助于复用预处理与模型，但还应记录依赖版本和输入契约。对象保存成功，不代表从不可信文件加载是安全的，也不代表不同版本必然兼容。
:::


## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 列出数值和类别列。
2. 为每类列定义子 Pipeline。
3. 用 ColumnTransformer 组合。
4. 与模型组成总 Pipeline。
5. 在训练数据 fit。
6. 用 CV 搜索内部参数。
7. 保存完整对象并验证加载预测。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
train = pd.DataFrame({"age": [20., 30., 40., 50.],
                      "income": [1., 2., 3., 4.], "city": ["A", "B", "A", "B"]})
future = pd.DataFrame({"age": [60.], "income": [5.], "city": ["C"]})
numeric = Pipeline([("imputer", SimpleImputer(strategy="median")),
                    ("scaler", StandardScaler())])
categorical = Pipeline([("imputer", SimpleImputer(strategy="most_frequent")),
                        ("one_hot", OneHotEncoder(handle_unknown="ignore", sparse_output=False))])
prep = ColumnTransformer([("numeric", numeric, ["age", "income"]),
                          ("categorical", categorical, ["city"])])
model = Pipeline([("preprocessor", prep), ("classifier", LogisticRegression())])
model.fit(train, [0, 0, 1, 1])
encoded = model.named_steps["preprocessor"].transform(future)
print("transformed_shape:", encoded.shape)
print("unknown_city:", encoded[0, -2:].tolist())
print("prediction:", model.predict(future).tolist())
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 数值两列加训练城市 A、B 的两列指示，共四列；未见城市 C 的两列均为零。
- 所有拟合只使用 train，未来表直接经同一条管线；本例不声称对新城市泛化已被验证。
:::

unknown_city: [0.0, 0.0]
prediction: [1]

- 只保存分类器不保存预处理

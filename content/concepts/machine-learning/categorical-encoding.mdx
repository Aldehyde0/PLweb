## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
城市、颜色或产品类型不是天然可计算的连续数值。简单用 0、1、2 代替名称，可能让线性模型或距离方法错误地认为类别具有大小顺序与等距关系。

编码应表达任务中允许的关系，并在训练和预测之间保持相同类别集合与列语义。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
One-Hot 为类别创建独立指示列；有序编码把具有真实顺序的类别映射到数值等级。无序类别编号与有意义的顺序等级不同，不能只因为都是整数就互相替代。

编码器的已学状态包括类别集合、输出顺序和未知值处理方式。它们与模型参数同样需要保存和复用。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
One-Hot 像为每种颜色准备一个开关，而不是把红色排在绿色之前。一个样本打开属于它的开关；具体哪一列代表哪种颜色，应看编码器输出，不能凭输入顺序猜测。
:::

### 输出列为什么不是按输入出现顺序排列

训练颜色按 red、green、blue 输入，编码器可能输出 blue、green、red 三列。此时 green 是 [0,1,0]，red 是 [0,0,1]，应读取 get_feature_names_out 或类别属性确认。

若未来遇到 yellow，忽略未知值的策略产生 [0,0,0]。这只是“训练集合里没有它”的表示，不代表黄色属于一种概率为零的真实业务类别；还应监控未知率。


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
训练时拟合类别集合，验证和预测只应用该集合。某类没有在训练中出现时，需要明确是报错、全零、并入其他类还是采用其他处理，而不是临时新增一列破坏模型接口。

handle_unknown='ignore' 常使未知类别对应全零编码，这能保持维度，但不会自动教模型理解新类别。若又删除了一个基准类别，全零还可能与该基准表示混在一起。

有序编码只应在等级顺序确实合理时采用，并继续检查数值距离的含义。例如“低、中、高”的次序存在，也不自动说明从低到中的差与从中到高完全相同。

高基数类别、缺失值与标签驱动编码有各自边界。目标编码尤其要防止把当前样本答案写回特征，通常需要折外构造与严格验证。
:::


## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 识别无序与有序类别。
2. 确定缺失类别处理。
3. 只在训练集拟合编码器。
4. 对验证和测试复用列空间。
5. 记录生成的特征名称。
6. 检查高基数类别带来的维度与稀疏性。
:::

:::field{path="codeExamples.0.purpose" type="text"}
训练时建立类别空间，预测时安全处理新类别。

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```scikit-learn
from sklearn.preprocessing import OneHotEncoder

encoder = OneHotEncoder(
    handle_unknown="ignore",
    sparse_output=False,
)
train = [["red"], ["green"], ["blue"]]
test = [["green"], ["yellow"]]
encoder.fit(train)
print(encoder.get_feature_names_out())
print(encoder.transform(test))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- fit 只从训练集学习 red/green/blue。
- yellow 未见过，因此对应所有已知类别列为 0。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 无序类别直接编码为 0/1/2
- 训练和预测独立 get\_dummies 导致列不一致
- 忽略高基数问题
:::

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
预处理器看起来只是清理或缩放数据，但它也可能从样本中学习状态，例如均值、填补值、类别集合和主成分。只隔离模型的 fit，而在全数据上提前预处理，仍可能发生泄漏。

关键问题不是代码位于“训练”文件还是“测试”文件，而是某一步真正读取了哪些样本来估计参数。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
fit 建立变换所需的已学状态，transform 应用这些状态；fit_transform 是在同一批拟合数据上组合执行两步。它不是可以对训练与测试都无条件调用的快捷键。

有些纯确定性变换不需要学习统计量，但仍应核对接口和使用的特征是否在预测时可获得，不能把“无需 fit”误解成“不会泄漏”。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
把预处理看成先制定一把尺子、再拿它测量新样本。每测一批测试数据就重新刻尺，得到的已不是同一套训练规则。
:::

### 测试值 100 不能把训练均值改掉

构造训练值 [0,2]，总体均值为 1、标准差为 1，因此新值 100 应变换为 99。对测试值单独重新 fit，反而会把它居中成 0，看起来“数值更规整”，但变换规则已经改变。

## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
应先确定训练边界，再让填补、缩放、特征选择和模型在该边界内学习。验证、测试与线上输入使用已拟合状态，不重新估计参数。

交叉验证存在多套训练边界：每折训练样本不同，所以应各自拟合预处理。Pipeline 能让这些步骤随估计器一起进入当前训练折，避免先处理全数据再 CV。

标签驱动的特征选择、目标编码和重采样也属于需要审查的步骤，不能因为它们不是最后的分类器就放在折外执行。某些变换还需要额外的折外编码设计。

最终保存应包含完整管线和输入契约。只保存模型、在预测时临时计算新均值，可能既改变模型语义，也使历史评价无法复现。
:::

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 在查看任何整体统计量前确定划分策略。
2. 保留最终测试集。
3. 只把训练数据传给预处理器 fit。
4. 对所有分块调用 transform。
5. 交叉验证时使用完整 Pipeline。
6. 保存预处理器与模型的完整组合。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler().fit([[0.0], [2.0]])
before = scaler.mean_.copy()
result = scaler.transform([[100.0]])
print(f"mean_before={before[0]:.1f}")
print(f"transformed={result[0, 0]:.1f}")
print(f"mean_after={scaler.mean_[0]:.1f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 总体标准差为 1，故 (100−1)/1=99。
- transform 使用 fit 保存的均值，未用测试值重新学习。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
mean_before=1.0
transformed=99.0
mean_after=1.0

## 实际应用 {#applications}

:::field{path="applications" type="list"}
- 缺失值填补
- 数值缩放
- 类别编码
- PCA 与特征选择
- 交叉验证
:::


## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 完整数据 fit\_transform 后再划分
- 测试集重新 fit
- 手工处理导致训练与预测规则不一致
:::

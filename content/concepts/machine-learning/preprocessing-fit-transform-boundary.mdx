## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
许多评价泄漏并不发生在分类器内部，而发生在模型之前。即使测试标签未被使用，只要测试特征参与计算均值、类别词表或选择阈值，评价就不再独立。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
预处理中的 fit 会从数据学习状态，例如填补中位数、标准化均值与标准差、One-Hot 类别集合或 PCA 方向；transform 只使用已学状态转换输入。

数据划分不是预处理之后的步骤，而是所有会学习参数的变换之前的边界。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
把测试集想成封存试卷。fit 相当于总结试卷规律，只有训练材料允许被总结；验证和测试只能按已有规则作答。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
正确顺序是 split → fit preprocessing on train → transform train/validation/test。

交叉验证时，每一折都拥有自己的训练边界，因此预处理器必须放进 Pipeline，让每个训练折独立 fit。
:::

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 在查看任何整体统计量前确定划分策略。
2. 保留最终测试集。
3. 只把训练数据传给预处理器 fit。
4. 对所有分块调用 transform。
5. 交叉验证时使用完整 Pipeline。
6. 保存预处理器与模型的完整组合。
:::

```scikit-learn
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(
    SimpleImputer(strategy="median"),
    StandardScaler(),
    LogisticRegression(max_iter=2000),
)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
```

## 实际应用 {#applications}

:::field{path="applications" type="list"}
- 缺失值填补
- 数值缩放
- 类别编码
- PCA 与特征选择
- 交叉验证
:::


## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 完整数据 fit\_transform 后再划分
- 测试集重新 fit
- 手工处理导致训练与预测规则不一致
:::

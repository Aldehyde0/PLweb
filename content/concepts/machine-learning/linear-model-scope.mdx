## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
线性模型能在高维文本上很有效，也可能无法分开简单的二维 XOR。关键不是输入维数看起来多复杂，而是选定表示中目标是否接近线性可分或可拟合。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
线性模型对选定特征表示作加权求和。原始输入中的弯曲边界可以通过非线性特征映射变成表示空间中的超平面，容量由表示与正则共同决定。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
在原纸上无法画直线分开的点，换一种坐标展开后可能可以。模型仍按直线规则工作，但你改变了它看到的坐标。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
原始特征线性分数只含各输入的加性贡献，不能自动表达乘法交互或局部阈值。但加入平方、交互、样条或领域特征后，同一个线性求和可在原空间形成非线性函数。

特征扩展会增加维度与共线性，需结合缩放和正则。高维稀疏表示可能很适合线性方法；盲目添加所有高阶多项式却会增加计算和过拟合风险，且外推时高次项增长很快。

判断适用边界可从验证残差、错误分组和非线性基线比较入手。线性模型快速、可检查，但不是天然因果模型；树、核和神经网络也要使用同样独立验证协议，不能仅凭结构复杂就认为更合适。
:::

### XOR 中加入交互特征

- 四个输入为 (0,0)、(0,1)、(1,0)、(1,1)
- 标签为 0、1、1、0

交互分数在四点上依次为 -0.5、0.5、0.5、-0.5，能表达 XOR。

新模型对扩展特征 (x1,x2,x1x2) 仍是线性求和，因此“线性模型”不等于“原始输入只能有直线关系”。特征映射和估计器应一起描述。

四点上的手工构造仅说明可表达性，不是外部测试表现。真实任务需要从训练数据选择特征，并在未用于构造规则的数据上验证。

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 建立缩放与正则的线性基线。
2. 查看独立验证残差与系统性错误，识别需要的交互。
3. 将特征构造放入训练流程，并与非线性基线公平比较。
:::

### XOR 中加入交互特征的最小验证
:::

:::field{path="codeExamples.0.language" type="text"}

:::

:::field{path="codeExamples.0.purpose" type="text"}
使用完整构造输入核对XOR 中加入交互特征，输出只表示本例计算。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```python
points = [(0, 0), (0, 1), (1, 0), (1, 1)]
linear = [a + b - 0.5 for a, b in points]
interaction = [a + b - 2 * a * b - 0.5 for a, b in points]
print("linear predictions:", [int(s >= 0) for s in linear])
print("interaction scores:", interaction)
print("interaction predictions:", [int(s >= 0) for s in interaction])
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 显示手工可表达性，不冒充拟合实验。
- 比较只在四个构造点上成立。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
linear predictions: [0, 1, 1, 1]
interaction scores: [-0.5, 0.5, 0.5, -0.5]
interaction predictions: [0, 1, 1, 0]
```
:::

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
L1 在零点不可按普通可微函数处理。近端梯度把可微的数据损失与非光滑惩罚分开：先沿平滑部分下降，再执行针对惩罚的近端运算。

这解释了为什么有些实现能够稳定地产生精确零系数，而不仅仅是把参数推得很接近零。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
对于平滑损失 g(w) 加 L1 项 λ||w||1，近端梯度先计算 z=w−η∇g(w)，再对 z 的每个坐标做阈值为 ηλ 的软阈值变换。

软阈值保留符号，并从绝对值中减去阈值，不足阈值的部分变成零。它不同于硬阈值直接保留所有大系数原值。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
第一步只考虑怎样改善数据拟合，第二步再按惩罚规则收缩。把它们分开，既能核对梯度，又能明确零值究竟在哪一步出现。
:::

### 梯度下降之后，再做一次收缩

给定 w=[1,-0.2,0.05]、平滑梯度 [2,-1,0.1]、η=0.1、λ=0.5。第一步 z=[0.8,-0.1,0.04]，第二步阈值为 0.05，得到 [0.75,-0.05,0]。

最后一个坐标不是因为梯度恰好为零才被删除，而是梯度步后的绝对值低于阈值。这个小算例只核对一次更新，并没有证明整个优化过程已经收敛。


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
阈值是学习率乘以惩罚强度，不应遗漏学习率。只改学习率但保持阈值不变，会实际改变正在优化的相对惩罚。

数据损失的梯度必须与所写目标的 sum/mean 和系数一致。梯度尺度写错，即使软阈值公式单独正确，整体也不是预期算法。

步长要与平滑损失的曲率及算法条件匹配。近端算子能处理非光滑项，并不意味着任意大步长都能收敛，或一轮更新就是最优解。

截距常按单独约定处理，不一定与权重一起阈值化；多输出、组稀疏或其他惩罚也不能无条件使用逐元素 L1 软阈值。
:::

::::code-example{index="0"}

:::field{path="codeExamples.0.title" type="text"}
### 把梯度步与近端步分开打印
:::

:::field{path="codeExamples.0.language" type="text"}
NumPy
:::

:::field{path="codeExamples.0.purpose" type="text"}
核对阈值 ηλ 与精确零值。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```NumPy
import numpy as np
w = np.array([1.0, -0.2, 0.05])
gradient = np.array([2.0, -1.0, 0.1])
rate, strength = 0.1, 0.5
z = w - rate * gradient
threshold = rate * strength
updated = np.sign(z) * np.maximum(np.abs(z) - threshold, 0.0)
print("gradient_step:", z.round(4).tolist())
print("proximal_step:", updated.round(4).tolist())
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 第一行只包含平滑梯度更新，第二行再施加 L1 近端映射。
- 真实训练还要重新计算梯度、检查停止条件及处理截距约定。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
gradient_step: [0.8, -0.1, 0.04]
proximal_step: [0.75, -0.05, 0.0]
:::

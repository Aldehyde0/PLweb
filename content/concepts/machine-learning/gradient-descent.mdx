## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
假设用一条直线预测房价，权重决定面积每增加一个单位时预测值增加多少，偏置决定整条直线上下移动多少。模型开始时并不知道合适的参数；训练需要把“预测偏了多少”转成“下一步该怎样改参数”。

在参数较少时，可以画图、列举候选值，某些模型也能直接求解析解。但神经网络可能有数百万个参数，逐个尝试通常不可行。梯度下降利用损失函数的局部变化率，把每次试探变成一个有方向的更新。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
导数回答一个局部问题：输入只改变很小一点时，函数值大约怎样变化。对单个参数 w，导数为正表示向右增大 w 会让函数在附近上升，导数为负表示附近向右反而下降。

模型有多个参数时，分别对每个参数求偏导，并按固定顺序组成梯度向量。这里其他参数保持不变；某一个偏导不是“所有参数一起变化”的结果。

梯度下降先在当前参数处计算梯度，再沿其反方向移动。它优化的是选定的训练目标；训练损失降低并不自动代表验证集表现提高。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
可以把损失曲面想成山坡，参数是当前位置。梯度提供脚下的局部坡向，学习率像每次迈出的步幅。坡度方向正确，步子过大仍可能跨过谷底，甚至越走越远。

“反方向”需要和导数的正负一起理解。例如梯度为 -6 时，更新式中减去一个负数，会让参数增大。这恰好是在当前点朝损失降低的方向移动，并不矛盾。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
一次标准更新包含两件不同的事：先用同一组旧参数计算损失和全部梯度，再用这些梯度更新参数。不能更新完第一个权重后，未经说明就用新权重重新计算第二个权重的梯度，否则实现的已不是同一个同步更新过程。

梯度只描述附近的变化。非凸目标可能出现局部极小值、鞍点或平坦区域；即使梯度很小，也要结合损失曲线、验证指标和参数变化判断训练是否合适。

批量梯度下降使用全部训练样本计算一次梯度；随机梯度下降使用单个样本，小批量方法使用一批样本。后两者的更新可能有噪声，因此不能要求每一步训练损失都严格下降。

特征尺度也会影响轨迹。如果一个特征以个位数计量、另一个以万为单位计量，损失曲面可能很狭长；标准化可以改善部分问题，但不能代替选择学习率、检查数据和使用合适的优化器。
:::

## 手算：三次更新怎样接近最低点 {#worked-example}

用一个只有一个参数的构造目标练习更新过程：$L(w)=(w-3)^2$，起点 $w_0=0$，学习率 $\eta=0.1$。它的导数是 $L'(w)=2(w-3)$，最小值位于 $w=3$。

| 更新前的 w | 当前梯度 | 更新后的 w | 损失（约） |
| --- | --- | --- | --- |
| 0 | -6 | 0 − 0.1 × (-6) = 0.6 | 5.76 |
| 0.6 | -4.8 | 0.6 − 0.1 × (-4.8) = 1.08 | 3.69 |
| 1.08 | -3.84 | 1.08 − 0.1 × (-3.84) = 1.464 | 2.36 |

表中损失保留两位小数，更新使用未舍入的参数。这里步子逐渐变小，是因为离最小值越近，梯度绝对值也越小。并不是代码额外设置了逐步衰减的学习率；本例学习率始终是 0.1。

把误差记为 $e_t=w_t-3$，可以直接推导 $e_{t+1}=(1-2\eta)e_t$。因此，**仅对这个二次目标**，当 $0<\eta<1$ 时误差逐步缩小；$\eta=1$ 会在两侧等幅来回跳，$\eta>1$ 会放大误差。不能把“1”当成所有模型的统一临界学习率。

上方互动图形默认从 -4 出发，而且学习率可调；本手算例与下面代码从 0 出发。比较图形和表格的具体数值前，要先对齐初始值和学习率，它们使用的是同一个更新公式。

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 明确输入、预测函数和要最小化的损失，记录一份初始损失作为比较基准。
2. 在训练数据上前向计算预测，再计算一个标量损失。
3. 用解析导数或自动微分计算当前参数的梯度，检查数值是否有限。
4. 使用同一次前向对应的梯度更新全部参数；自动微分框架中还需正确清理累计梯度。
5. 记录训练损失、参数或梯度变化，并在独立验证数据上检查泛化表现。
6. 达到迭代预算、变化阈值或早停条件时停止；最后才按既定协议评估测试集。
:::

### 用 20 次梯度更新核对手算过程

:::field{path="codeExamples.0.purpose" type="text"}

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
w = 0.0
learning_rate = 0.1
for _ in range(20):
    gradient = 2 * (w - 3)
    w -= learning_rate * gradient
loss = (w - 3) ** 2
print(f"w={w:.4f}, loss={loss:.6f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 导数 2×(w−3) 来自当前例子的损失函数，不是对任意模型都适用的更新方向。
- 前 3 次更新与上面的手算表一致；20 次后接近 3，但有限次迭代通常不会恰好等于 3。
- 这里只优化一个构造函数，没有训练集或测试集，不能把损失数值解读成真实模型的预测质量。
:::

### 只改变学习率：收敛、震荡和发散
:::

:::field{path="codeExamples.1.language" type="text"}
Python
:::

:::field{path="codeExamples.1.purpose" type="text"}
使用同一起点和迭代次数，观察学习率对本例轨迹的影响。

:::field{path="codeExamples.1.source" type="code" trailing="0"}
```Python
for rate in [0.1, 0.8, 1.1]:
    w = 0.0
    for _ in range(4):
        w -= rate * 2 * (w - 3)
    print(f"eta={rate:.1f} w={w:.4f} loss={(w - 3) ** 2:.4f}")
```
:::

:::field{path="codeExamples.1.explanation" type="list"}
- 三个实验都从 0 出发，且都进行 4 次更新。
- 0.8 会跨过最小值来回移动，但误差仍缩小；震荡不一定意味着发散。
- 1.1 在这个二次函数上放大误差，4 步后的损失反而大于初始损失 9。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 认为“梯度为负就应该减小参数”：应代入更新式检查符号，减去负梯度会增大参数。
- 把某个示例的学习率范围当成所有模型的通用安全范围；稳定步长依赖损失的曲率与尺度。
- 把训练损失变小等同于泛化变好，或只看最后一个批次的损失就宣布收敛。
- 遇到 NaN、无穷大或持续震荡时只增加迭代次数，却不检查数据、学习率、梯度和数值稳定性。
:::

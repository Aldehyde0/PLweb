## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
一次随机划分可能碰巧包含容易或困难样本，导致对模型的判断不稳定。交叉验证在开发数据内轮流留出不同部分，让我们观察同一训练流程在多个验证子集上的表现。

它评估的是给定训练与划分流程，不会自动解决泄漏，也不会因为用了多个折就消除模型选择带来的偏差。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
第 k 折用其余 K-1 折训练，本折验证；交叉验证用于模型选择，不替代最终测试。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
进行多轮模拟考试，而不是只凭一次成绩。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
K 折把开发集划成 K 个验证子集。每轮从其余部分重新拟合模型，再预测当前验证折；每个样本在标准 K 折中恰好验证一次，模型也会被重新训练 K 次。

预处理必须一起重新拟合。填补、缩放与特征选择应在当前训练折中学习，验证折只应用对应变换；通过 Pipeline 包装能让这些边界随每轮训练保持一致。

分层、群组和时间划分对应不同的数据结构。选择划分器之前，应明确要推广到新行、新实体还是未来时间；普通随机 K 折不适合所有情境。

每折分数可以汇总均值与波动，但各训练折共享数据，折分数不是相互独立的重复实验。CV 也不负责把最终模型自动交付：模型选择后通常在完整开发集上另行拟合，再用保留测试集做最终评价。
:::

$$
s̄=(1/K)Σsₖ；scv=√[Σ(sₖ-s̄)²/(K-1)]

### 案例：150 行开发数据做 3 折验证

用内置 Iris 的 150 行演示 3 折分层验证，每轮训练 100 行、验证 50 行。标准化与逻辑回归一起在训练折拟合，输出 3 个验证分数，而不是一份模型对训练数据的分数。

下方还检查传入的原始估计器没有在原地被拟合。交叉验证使用副本完成各折；若要部署，需要在固定方案后显式 fit 最终流程。这里没有单独测试集，输出仅是教学数据上的开发分数。

## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 保留测试集
2. 选择划分器
3. 固定折
4. 折内 Pipeline fit
5. 收集每折指标
6. 报告均值/标准差
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_iris(return_X_y=True)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(3, shuffle=True, random_state=42)
result = cross_validate(model, X, y, cv=cv, scoring="accuracy")
print("fold_accuracy:", result["test_score"].round(3).tolist())
print(f"mean={result['test_score'].mean():.3f}")
print("original_model_fitted:", hasattr(model.named_steps["logisticregression"], "classes_"))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 每轮使用新的 Pipeline 副本，缩放只在训练折学习。
- 原始模型没有 classes_，提示 CV 与最终 refit 是两步。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- CV 前就对全数据拟合预处理，或只报告最好的一折。
- 把折间标准差当作独立样本标准误，或用 CV 代替所有最终测试。
- 以为 cross_validate 已经把原始 estimator 拟合成可部署模型。
:::

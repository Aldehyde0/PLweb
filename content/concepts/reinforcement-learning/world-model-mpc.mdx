## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
机器人推箱子时，可以用模型预测若干动作序列的后果，选择眼前较好的计划。但执行第一步后，摩擦和碰撞可能使箱子偏离预测，继续盲目执行整串动作会放大误差。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
世界模型预测环境未来，可能在物理状态、观察或潜在空间中建模。模型预测控制 MPC 在当前信息下搜索有限时域动作序列，只执行首个动作，然后更新状态估计并重规划。世界模型是预测工具，MPC 是使用模型的决策过程。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
导航先规划一段路线，开过一个路口后根据实际位置和新路况再算。重新规划能纠正部分预测误差，但如果地图系统性错误，反复算错也不会自动变正确。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
计划目标可累加预测奖励并加末端价值，还需满足动作和状态约束。有限时域太短会看不到先付成本后获收益的机会，末端价值可缓解短视，但自身也有估计误差。

模型在真实数据分布上准确，不保证在优化器搜索的所有动作序列上准确；规划可能主动利用模型漏洞。限制预测长度、惩罚模型不确定性或使用模型集合都需要独立验证。

每步重规划增加计算成本，真实执行还受延迟和状态估计质量影响。不能把模拟 rollout 数量当作真实环境样本效率，也不能仅以模型单步均方误差代替闭环控制评价。
:::

### 有限时域模型规划
:::

:::field{path="formulas.0.expression" type="math"}
$$
a_{t:t+H-1}^*=\arg\max\sum_{k=0}^{H-1}\gamma^k\hat r(\hat s_{t+k},a_{t+k})
$$

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 两步规划为何先执行看似不最优的动作
:::

:::field{path="numericalExample.given" type="list"}
- 确定模型 x′=x+a，x0=0，目标位置 2，动作只能取 0 或 1。
- 两步成本为每步后位置误差平方之和。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 序列 [0,1] 的代价为 (0−2)²+(1−2)²=5。
2. 序列 [1,1] 的代价为 (1−2)²+(2−2)²=1，是最小值。
3. MPC 只执行第一个 1，收到真实新状态后再规划。
:::

:::field{path="numericalExample.result" type="text"}
最优两步计划为 [1,1]，但本轮实际只执行首动作 1。
:::

:::field{path="numericalExample.comparison" type="list"}
- 计划长度与一次实际执行的动作数不同。
- 示例模型恰好正确，真实任务还需考虑模型误差和观测噪声。
:::

## 代码实现 {#code}

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 两步规划为何先执行看似不最优的动作
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
最优两步计划为 [1,1]，但本轮实际只执行首动作 1。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
from itertools import product
costs = {}
for actions in product([0, 1], repeat=2):
    x, cost = 0, 0
    for action in actions:
        x += action
        cost += (x - 2) ** 2
    costs[actions] = cost
best = min(costs, key=costs.get)
print(f"plan={best}, cost={costs[best]}, execute_first={best[0]}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 序列 [0,1] 的代价为 (0−2)²+(1−2)²=5。
- 序列 [1,1] 的代价为 (1−2)²+(2−2)²=1，是最小值。
- MPC 只执行第一个 1，收到真实新状态后再规划。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
plan=(1, 1), cost=1, execute_first=1
```

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 执行整串预测动作却仍称每步重规划。
- 短 horizon 没有末端价值，漏掉延迟收益。
- 规划器反复搜索数据外区域，利用模型错误。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 执行整串预测动作却仍称每步重规划。
- 短 horizon 没有末端价值，漏掉延迟收益。
- 规划器反复搜索数据外区域，利用模型错误。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 每步重规划能消除模型误差吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
能利用新观察纠正部分偏离，但系统性模型错误、隐藏状态和控制延迟仍会影响闭环结果，需要按真实任务验证。
:::

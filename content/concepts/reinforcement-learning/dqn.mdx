## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
图像输入有大量可能状态，表格不能逐个存储 Q。DQN 用一个网络从观察直接输出有限动作的价值，允许状态间共享表示；同时神经网络和不断变化的 bootstrap 目标使训练比小表格更敏感。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
DQN 是面向离散动作的深度 Q-learning：在线网络预测 Q(s,a)，延迟更新的目标网络提供后继最大 Q，训练从回放缓冲区抽取转移。行为通常用 ε-greedy 采样，因此学习贪心目标时是 off-policy。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
在线网络像正在修订的评分表，目标网络像暂时冻结的参考版本。每一步都追逐同一张正在快速变化的表，容易让目标与预测互相拉动；延迟参考可缓解这种现象。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
一个批次先对所有状态前向，按实际动作索引抽取 Q(s,a)；损失只直接约束采样动作。下一状态的最大值应在无梯度路径中计算，不让目标分支和预测一起追逐当前残差。

Replay 提高样本复用并减弱相邻样本相关性，但不创造缺失覆盖。目标网络降低变化速度，也不能保证非线性学习收敛；目标同步周期过短或过长均可能影响训练。

普通 DQN 在目标网络上同时选最大动作和评价，因此仍有最大化偏差。Double DQN 将选择与评价分开；dueling 则改变网络结构，二者解决的问题不同。下方代码只做构造批次的一次更新，不是游戏成绩实验。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 两个样本中终止掩码怎样影响 DQN 目标
:::

:::field{path="numericalExample.given" type="list"}
- 奖励分别为 1、2，后继最大 Q 分别为 3、100。
- 第二样本真正终止，折扣 0.9。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 第一样本目标为 1+0.9×3=3.7。
2. 第二样本必须屏蔽后继 100，目标仅为 2。
3. 若漏掉终止掩码，第二目标会错误地变成 92。
:::

:::field{path="numericalExample.result" type="text"}
正确目标为 3.7 和 2.0；第二后继的高值与已终止任务无关。
:::

:::field{path="numericalExample.comparison" type="list"}
- DQN 学习离散动作 Q，不能直接枚举无限连续动作。
- 一次神经网络批次更新只验证张量与目标计算，不代表策略已学会环境。
:::

### PyTorch DQN：Online、Target 与 Replay 的最小训练步
:::

:::field{path="codeExamples.0.language" type="text"}
PyTorch
:::

:::field{path="codeExamples.0.purpose" type="text"}
完整展示批次张量、DQN target、Huber loss、反向传播和 Target Network 同步。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```PyTorch
import random
from collections import deque
import torch
from torch import nn

torch.manual_seed(7)
online = nn.Sequential(nn.Linear(4, 32), nn.ReLU(), nn.Linear(32, 2))
target = nn.Sequential(nn.Linear(4, 32), nn.ReLU(), nn.Linear(32, 2))
target.load_state_dict(online.state_dict())
target.eval()
optimizer = torch.optim.Adam(online.parameters(), lr=1e-3)
replay = deque(maxlen=1000)

for i in range(64):
    state = torch.tensor([i % 4 == j for j in range(4)], dtype=torch.float32)
    next_state = torch.roll(state, 1)
    replay.append((state, i % 2, 1.0 if i % 7 == 0 else 0.0, next_state, False))

batch = random.Random(7).sample(list(replay), 32)
states = torch.stack([x[0] for x in batch])
actions = torch.tensor([x[1] for x in batch]).unsqueeze(1)
rewards = torch.tensor([x[2] for x in batch])
next_states = torch.stack([x[3] for x in batch])
dones = torch.tensor([x[4] for x in batch], dtype=torch.float32)

q_sa = online(states).gather(1, actions).squeeze(1)
with torch.no_grad():
    next_q = target(next_states).max(1).values
    td_target = rewards + 0.99 * (1 - dones) * next_q
loss = nn.SmoothL1Loss()(q_sa, td_target)
optimizer.zero_grad()
loss.backward()
nn.utils.clip_grad_norm_(online.parameters(), 10.0)
optimizer.step()
target.load_state_dict(online.state_dict())
print('loss:', round(loss.item(), 4))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- Replay 打破连续样本相关性，并允许重复利用数据。
- Online Network 产生 Q(s,a)，Target Network 产生相对稳定的 TD 目标。
- SmoothL1Loss、梯度裁剪和周期性 Target 同步共同改善稳定性。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- gather 的动作维度错误，让损失拟合了不对应的动作。
- 目标分支未停止梯度，或真正终止仍使用后继值。
- 把单次构造数据 loss 下降当成环境策略改善。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- gather 的动作维度错误，让损失拟合了不对应的动作。
- 目标分支未停止梯度，或真正终止仍使用后继值。
- 把单次构造数据 loss 下降当成环境策略改善。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### DQN 有 replay 就能直接用于任意离线数据吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
不能。固定数据下 max 可能选择没有覆盖的高估动作，需单独处理离线分布偏移，不能把在线 DQN 的常规经验直接视为可靠离线方法。
:::

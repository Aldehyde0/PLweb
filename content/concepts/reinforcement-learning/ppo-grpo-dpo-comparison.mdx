## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
PPO、GRPO、DPO 都用于语言模型后训练，却不要求相同数据。把三者放进同一个名称列表而不写数据流程，会误以为只改一个损失函数就能互换，实际需要的采样、评分和模型组件明显不同。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
PPO 是通用策略优化方法，语言 RLHF 中通常配价值模型与生成评分。GRPO 用同 prompt 的多响应相对奖励替代独立价值基线，并保留 PPO 风格更新。DPO 直接用离线偏好对和参考策略构造损失，不要求传统在线环境交互。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
PPO 像教练给每次表现一个相对预期评价；GRPO 像同题多份答卷互相比较；DPO 像根据已有的两两胜负记录调整偏好。三种记录格式不能不经转换就互相代替。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
PPO 的优势可由 critic 与 GAE 构造，GRPO 原始设计用组均值与标准差构造相对优势。两者都要正确保存旧策略概率，裁剪目标也都不是硬性 KL 保证；评分可来自模型或可验证规则。

DPO 的核心输入是相同 prompt 的优选和拒绝响应，参考策略用于相对 log 概率。它没有与环境转移一一对应的 TD 目标，也不应只因为理论联系就称为在线 RL。

比较资源需计算生成 token、评分、参考推断、价值模型和训练更新，而非只数网络个数。GRPO 省 critic 可能增加每 prompt 采样数；DPO 省在线生成但需要先获得有代表性的偏好数据。
:::


## 数学表达 {#formulas}

::::formula{index="0"}
:::field{path="formulas.0.label" type="text"}
### 在线概率比率与离线偏好 logit
:::

:::field{path="formulas.0.expression" type="math"}
$$
\rho_t=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)},\qquad z_{DPO}=\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}\right]
$$
:::

:::field{path="formulas.0.description" type="text"}
PPO 与 GRPO 使用近期采样的概率比率但优势构造不同；DPO 用偏好对的相对 logit，输入不能直接互换。
:::

:::field{path="numericalExample.title" type="text"}
### 相同 prompt 数量不代表相同采样成本
:::

:::field{path="numericalExample.given" type="list"}
- 构造一个最小数据清单：3 个 prompt。
- PPO 每题新采 1 个响应；GRPO 每题新采 4 个；DPO 每题已有 1 对偏好。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. PPO 本轮生成 3 个响应，GRPO 生成 12 个。
2. DPO 读取 3 对、共 6 个已存响应，本轮目标不要求新生成。
3. 只数响应仍未包含长度、评分和反向传播成本，不能据此给性能排名。
:::

:::field{path="numericalExample.result" type="text"}
示例清单为 3 个 PPO 新响应、12 个 GRPO 新响应、6 个 DPO 存储响应。
:::

:::field{path="numericalExample.comparison" type="list"}
- 三者的反馈格式与采样流程不同。
- 响应数是配置算术，不是真实吞吐或模型质量基准。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 以为三种方法只要相同 batch 就能直接换损失。
- 把 GRPO 省 critic 解读成总成本必然更低。
- 把 DPO 的静态偏好训练描述成环境探索。
:::

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 只有偏好对时应直接使用 PPO 吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
PPO 需要可用于其 rollout 的奖励与优势流程；仅有静态偏好对时，DPO 或奖励建模是更直接的数据接口，仍要按任务验证。
:::

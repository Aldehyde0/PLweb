## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
已有同一问题下的人类优选与拒绝回答时，可以直接提高相对偏好概率。DPO 利用带 KL 约束奖励优化的最优策略关系，把一类 RLHF 目标改写成偏好分类式损失，减少独立奖励模型和在线采样循环的需求。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
DPO 用当前策略与固定参考策略在优选、拒绝回答上的对数概率差，形成偏好 logit 并最小化负 log-sigmoid。标准训练输入是离线偏好对；它与在线 RL 有目标推导联系，但不应直接归入普通 on-policy 或 off-policy MDP 控制算法。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
不是要求绝对提高每份好答案的概率，而是要求相对参考策略，更偏向优选而不是拒绝答案。两条概率都变化时，真正起作用的是相对差距的变化。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
参考策略的优选与拒绝 log 概率都要扣除。若只用当前策略的差，就失去 DPO 中参考约束的目标含义。β 调节相对 logit 尺度，其影响需结合数据与优化过程，不能简化为任意训练下越大或越小越好。

序列对数概率通常由回答 token 的条件 log 概率求和，prompt 和 padding 掩码必须正确。长度归一化属于目标变体，会改变偏好关系的权重，不能默默平均后仍宣称与原式完全相同。

偏好数据可能有评审偏差、矛盾或覆盖不足。损失下降表示更符合已提供的比较，不保证事实性、安全性或未见问题质量；新策略生成的数据若再回流，应明确这是扩展的数据迭代流程。
:::


## 数学表达 {#formulas}

::::formula{index="0"}
:::field{path="formulas.0.label" type="text"}
### DPO loss
:::

:::field{path="formulas.0.expression" type="math"}
$$
\mathcal{L}_{DPO}=-\mathbb{E}_{(x,y_w,y_l)}\log\sigma(\beta[\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}])
$$
:::

:::field{path="formulas.0.description" type="text"}
提高 chosen 相对 reference 的优势，并降低 rejected。
:::

## 代码实现 {#code}

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### DPO loss：chosen / rejected 与 reference 的对数概率差
:::

:::field{path="codeExamples.0.language" type="text"}
PyTorch
:::

:::field{path="codeExamples.0.purpose" type="text"}
根据 DPO 原论文目标计算一个偏好对损失，不训练 Reward Model、不采样在线轨迹。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```PyTorch
import torch
import torch.nn.functional as F

beta = 0.1
policy_chosen = torch.tensor([-1.2, -0.8], requires_grad=True)
policy_rejected = torch.tensor([-2.0, -1.1], requires_grad=True)
reference_chosen = torch.tensor([-1.4, -0.9])
reference_rejected = torch.tensor([-1.8, -1.0])

policy_margin = policy_chosen - policy_rejected
reference_margin = reference_chosen - reference_rejected
logits = beta * (policy_margin - reference_margin)
loss = -F.logsigmoid(logits).mean()
loss.backward()
print('preference logits:', logits.detach())
print('DPO loss:', round(loss.item(), 4))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 每行数据包含 chosen 与 rejected 响应的序列对数概率。
- 策略偏好 margin 与 reference margin 的差经 beta 缩放。
- 负 log-sigmoid 是二分类式偏好损失；这不是标准 MDP 在线交互循环。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
preference logits: tensor([0.0400, 0.0200])
DPO loss: 0.6783
```
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 省略参考策略 margin，却仍称标准 DPO。
- 把 prompt 和 padding 的 token 误计入回答 log 概率。
- 把离线偏好损失下降等同于在线环境回报提高。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}

- 把 prompt 和 padding 的 token 误计入回答 log 概率。

:::field{path="securityRisks" type="list"}

:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。

## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### DPO 是 on-policy 还是 off-policy RL？
:::

:::field{path="commonQuestions.0.answer" type="text"}
标准 DPO 是离线偏好优化目标，不宜强行套入传统 MDP 采样分类。它的输入、目标和在线 PPO/GRPO 的生成评分循环不同。
:::

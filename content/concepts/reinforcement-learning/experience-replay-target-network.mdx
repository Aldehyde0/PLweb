## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
连续采集的相邻图像高度相似，而 Q 网络每次更新还会改变下一批目标。直接按时间顺序追逐这些目标，既可能浪费样本，又容易让估计发生正反馈；replay 和目标网络从不同方向缓解问题。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
经验回放保存状态、动作、奖励、后继与终止信息，训练时抽样复用。目标网络是在线网络的延迟副本，构造较缓慢变化的 bootstrap 目标。它们常配合使用，但一个改变数据采样，另一个改变目标更新速度。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
Replay 像把不同日期的练习题混在一起复习；目标网络像阶段性固定参考答案。混题不保证每题都正确，固定答案也不保证答案永远适合当前阶段。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
缓冲区容量和采样方式决定训练看见的新旧数据比例。过小缓冲仍高度相关，过旧数据可能和当前状态分布差异很大；on-policy 算法不能不加处理地套用任意旧回放。

目标网络可定期硬复制，也可软更新。若软更新式写成 target=(1−τ)target+τ online，τ 越小变化越慢；不同库可能对 Polyak 系数使用相反命名，必须看公式。

目标计算一般停止梯度。真正终止与纯截断仍需分别处理，自动重置时还要保存结束前后继观察；replay 里错误的数据边界会在每次重放时重复放大。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 软更新只是移动目标，不是一次完整复制
:::

:::field{path="numericalExample.given" type="list"}
- 在线参数为 10，旧目标参数为 2。
- 使用 target=(1−τ)target+τ online，τ=0.1。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 旧目标贡献为 0.9×2=1.8。
2. 在线参数贡献为 0.1×10=1。
3. 新目标为 2.8，仍明显滞后于在线参数 10。
:::

:::field{path="numericalExample.result" type="text"}
软更新后目标参数由 2.000 变为 2.800。
:::

:::field{path="numericalExample.comparison" type="list"}
- 硬同步会一次复制为 10，软更新只移动一部分。
- 该标量例说明参数更新，不直接给出策略性能。
:::

## 常见错误 {#pitfalls}

- 以为随机抽样能修复错误奖励和终止标记。
- 对 on-policy 数据无限回放而不处理策略变化。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 将软更新中 τ 的含义与库的 Polyak 系数混淆。
- 以为随机抽样能修复错误奖励和终止标记。
- 对 on-policy 数据无限回放而不处理策略变化。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 目标网络需要反向传播更新吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
通常通过复制或软更新获得参数，TD 目标分支停止梯度；它不是在同一次损失中与在线预测一起被任意调整。
:::

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
深度强化学习的失败可能来自网络，也可能只是坐标轴写反或目标格没有终止。GridWorld 将这些因素缩小到能完整打印的状态表，使学习器和环境可以分别验证。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
GridWorld 用格子、方向与转移规则构造有限决策环境。状态可包含位置、钥匙或剩余时间；上下左右等是动作。它是一类环境而不是单个算法，同一网格可以用 DP、MC、TD 或策略方法求解。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
像在方格纸上推演路线：先明确撞墙是否原地停留、到终点何时拿奖励，再讨论策略。不同规则即使图看起来一样，也可能是不同 MDP。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
必须定义坐标顺序、地图边界、障碍、起点分布、转移随机性和奖励时机。撞墙保持原地与允许越界不是小实现差异，会改变状态转移和最优路线。

终点可约定为进入时给奖励并立即终止；此后不再叠加终点自身价值。若终点仍可循环领取奖励，任务会从“到达目标”变成“持续刷分”，策略目标已经不同。

可先验证一条固定动作序列的状态、奖励和终止，再比较学得策略与已知最短路径。最短路径只在确定环境且奖励按步长等条件下对应最优回报，带滑动概率或风险时未必如此。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 边界动作与目标奖励的明确约定
:::

:::field{path="numericalExample.given" type="list"}
- 2×2 网格，起点 (0,0)，终点 (1,1)。
- 向上越界时原地停留，普通步奖励 −1，进入终点奖励 +5。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 从起点向上后仍为 (0,0)，奖励 −1。
2. 随后向右到 (0,1)，奖励 −1。
3. 再向下到终点 (1,1)，奖励 +5 并终止。
:::

:::field{path="numericalExample.result" type="text"}
固定三步得到奖励 −1、−1、5，总和为 3；边界动作消耗一步。
:::

:::field{path="numericalExample.comparison" type="list"}
- 撞墙规则和奖励时机是环境定义的一部分。
- 本例用不折扣有限轨迹求和，未进行策略训练。
:::


## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. reset 起点
2. epsilon-greedy 选动作
3. 执行移动
4. 更新 Q
5. 到终点结束
:::

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### 边界动作与目标奖励的明确约定
:::

:::field{path="codeExamples.0.language" type="text"}
Python
:::

:::field{path="codeExamples.0.purpose" type="text"}
固定三步得到奖励 −1、−1、5，总和为 3；边界动作消耗一步。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
state, goal = (0, 0), (1, 1)
total = 0
for dr, dc in [(-1, 0), (0, 1), (1, 0)]:
    row, column = state[0] + dr, state[1] + dc
    if 0 <= row < 2 and 0 <= column < 2:
        state = (row, column)
    terminal = state == goal
    reward = 5 if terminal else -1
    total += reward
    print(f"state={state} reward={reward} terminal={terminal}")
    if terminal:
        break
print(f"total={total}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 从起点向上后仍为 (0,0)，奖励 −1。
- 随后向右到 (0,1)，奖励 −1。
- 再向下到终点 (1,1)，奖励 +5 并终止。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
state=(0, 0) reward=-1 terminal=False
state=(0, 1) reward=-1 terminal=False
state=(1, 1) reward=5 terminal=True
total=3
```
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 行列坐标与上下方向符号混用。
- 进入终点后继续领取正奖励。
- 有随机陷阱时仍把几何最短路径当唯一正确答案。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 行列坐标与上下方向符号混用。
- 进入终点后继续领取正奖励。
- 有随机陷阱时仍把几何最短路径当唯一正确答案。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

### GridWorld 太简单，还有验证价值吗？

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
一个驾驶员用带随机探索的路线采集数据，学习器却想评估始终选择最快路线的策略。两者面对的是不同的动作分布；未经处理直接平均历史奖励，通常是在评价采样驾驶员，而不是目标策略。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
行为策略生成实际动作，目标策略是学习器要评价或改进的策略。on-policy 在与目标匹配的数据分布下学习；off-policy 允许二者不同。online/offline 描述能否继续收集数据，是另一条分类轴。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
用“按城市人群比例抽到的问卷”估计某个特殊群体偏好，需要检查样本来源；直接平均往往回答了另一个人群的问题。强化学习还增加了动作改变后续状态分布的困难。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
SARSA 的下一动作来自行为策略，因此其 TD 目标包含当前探索行为的后果。Q-learning 则使用贪心最大值作为目标，即使行为仍在 ε-greedy 探索，也是典型 off-policy 控制。

重要性采样以目标概率除以行为概率修正分布，但需要目标支持包含于行为支持。若行为从不尝试某动作，就无法靠除法恢复它的结果；长轨迹比率乘积还可能造成极大方差。

off-policy 不意味着任意旧数据都能稳定复用。函数近似、自举和分布偏差叠加时可能发散；PPO 使用固定旧策略的小批数据做有限轮更新，也不能据此无限使用任意 replay。
:::


## 数学表达 {#formulas}

::::formula{index="0"}
:::field{path="formulas.0.label" type="text"}
### 单步重要性比率
:::

:::field{path="formulas.0.expression" type="math"}
$$
\rho_t=\frac{\pi(A_t\mid S_t)}{\mu(A_t\mid S_t)}
$$
:::

:::field{path="formulas.0.description" type="text"}
μ 为行为策略；若目标策略有正概率，行为策略也必须提供正概率支持。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 单步重要性加权改变估计对象
:::

:::field{path="numericalExample.given" type="list"}
- 行为策略动作概率为 0.8、0.2；目标策略为 0.5、0.5。
- 动作奖励分别为 1、3，行为与目标均覆盖两个动作。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 行为策略的期望奖励为 0.8×1+0.2×3=1.4。
2. 两个重要性比率是 0.5/0.8=0.625 和 0.5/0.2=2.5。
3. 加权期望为 0.8×0.625×1+0.2×2.5×3=2。
:::

:::field{path="numericalExample.result" type="text"}
行为期望为 1.400，修正后的目标策略期望为 2.000。
:::

:::field{path="numericalExample.comparison" type="list"}
- 重要性采样能修正已有支持上的分布差异。
- 离线数据缺少目标动作时，本例的计算条件不成立。
:::

### 单步重要性加权改变估计对象
:::

:::field{path="codeExamples.0.language" type="text"}

:::

:::field{path="codeExamples.0.purpose" type="text"}

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
behavior = [0.8, 0.2]
target = [0.5, 0.5]
reward = [1.0, 3.0]
raw = sum(p * r for p, r in zip(behavior, reward))
corrected = sum(b * (t / b) * r for b, t, r in zip(behavior, target, reward))
print(f"behavior_value={raw:.3f}, target_value={corrected:.3f}")
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 行为策略的期望奖励为 0.8×1+0.2×3=1.4。
- 两个重要性比率是 0.5/0.8=0.625 和 0.5/0.2=2.5。
- 加权期望为 0.8×0.625×1+0.2×2.5×3=2。
:::

:::field{path="codeExamples.0.expectedOutput" type="text"}
```text
behavior_value=1.400, target_value=2.000
```

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 把 off-policy 误写成不能与环境交互。
- 对行为概率为零的目标动作直接做重要性加权。
- 认为使用 replay 就自动解决了全部分布偏差。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 把 off-policy 误写成不能与环境交互。
- 对行为概率为零的目标动作直接做重要性加权。

:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### off-policy 和 offline 是同义词吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
不是。SAC 可以在线交互并用旧 replay 做 off-policy 更新；offline RL 在训练期间不允许用当前策略向环境收集新样本。
:::

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
最简单的策略优化可以先跑完一局，计算每个动作之后实际得到的回报，再增加高回报动作的对数概率。这样无需学习后继价值网络，但整局随机结果会给早期动作带来很大的梯度波动。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
REINFORCE 是基于采样回报的 score-function 策略梯度方法。每个时间步可使用从该步起的 return-to-go，配合只依赖状态的基线降低方差。它使用完整回报作为学习信号，标准 episodic 形式不在回报目标中 bootstrap。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
一局结束后复盘，而不是每走一步就用评论家的猜测补足未来。复盘能利用真实结果，但一次幸运胜利仍可能让无关动作得到过多奖励。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
return-to-go 排除动作之前已经发生的奖励，因为当前动作不能改变过去。在折扣目标下，外部时间权重与回报定义要保持一致；不同实现的采样约定应说明，不能只抄一个损失就宣称严格相同。

优化器通常最小化负的 log_prob×advantage；漏掉负号会反向惩罚好动作。基线只改变梯度信号的中心，不应在同一个 actor 项中变成可任意追逐的目标。

下方例子用固定种子采一个离散动作，显示优势加熵项的梯度。它只证明概率分布和梯度路径可计算，不包含真实环境采样、完整 episode 累积或多轮训练表现。
:::

## 完整数值示例 {#numerical-example}

:::field{path="numericalExample.title" type="text"}
### 优势符号决定同一动作的更新方向
:::

:::field{path="numericalExample.given" type="list"}
- 一次完整轨迹回报为 2，状态基线为 1.2。
- 该动作概率的 score 梯度为 0.4，学习率 0.1。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 优势为 2−1.2=0.8。
2. 策略上升增量为 0.1×0.8×0.4=0.032。
3. 若基线为 2.5，优势变成 −0.5，同一 score 方向的增量为 −0.02。
:::

:::field{path="numericalExample.result" type="text"}
相同正回报在不同基线下可高于或低于预期，梯度方向由优势符号决定。
:::

:::field{path="numericalExample.comparison" type="list"}
- REINFORCE 使用采样回报，actor-critic 常用 bootstrap 优势。
- 下方可运行例还加入小熵奖励，它是探索正则，不是额外环境回报。
:::

## 代码实现 {#code}

::::code-example{index="0"}
:::field{path="codeExamples.0.title" type="text"}
### REINFORCE：轨迹回报乘对数概率
:::

:::field{path="codeExamples.0.language" type="text"}
PyTorch
:::

:::field{path="codeExamples.0.purpose" type="text"}
展示概率策略、轨迹回报、baseline 与熵奖励如何进入损失。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```PyTorch
import torch
from torch.distributions import Categorical

torch.manual_seed(7)
logits = torch.tensor([0.2, -0.1], requires_grad=True)
policy = Categorical(logits=logits)
action = policy.sample()
log_prob = policy.log_prob(action)
entropy = policy.entropy()
trajectory_return = torch.tensor(2.0)
baseline = torch.tensor(1.2)
advantage = trajectory_return - baseline
loss = -(log_prob * advantage + 0.01 * entropy)
loss.backward()
print('action:', action.item())
print('probabilities:', policy.probs.detach())
print('gradient:', logits.grad)
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- Categorical 表示随机策略，采样动作保留探索。
- 回报减 baseline 得到 advantage；baseline 不改变期望梯度但可降低方差。
- 熵项鼓励分布不要过早塌缩。
:::


## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 对最小化优化器使用正 log_prob×return，方向写反。
- 把整局总奖励用于所有时刻却不说明高方差问题。
- 将学习基线说成使 REINFORCE 变成了 bootstrap 回报。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 对最小化优化器使用正 log_prob×return，方向写反。
- 把整局总奖励用于所有时刻却不说明高方差问题。
- 将学习基线说成使 REINFORCE 变成了 bootstrap 回报。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 加入状态价值基线后仍算 REINFORCE 吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
可以。若 actor 的目标仍使用完整 Monte Carlo 回报减去状态基线，它仍属于基于回报的策略梯度；是否 bootstrap 要看目标具体构造。
:::

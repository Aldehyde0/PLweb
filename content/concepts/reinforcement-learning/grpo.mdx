## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
为语言回答训练独立 value model 会增加资源与工程成本。GRPO 对同一问题采样多个回答，用它们之间的奖励差形成相对优势，减少对独立 critic 的需求；这并不意味着可以不采样或不提供评分。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
DeepSeekMath 的 GRPO 是 PPO 风格策略优化变体：同 prompt 的一组响应共享组均值与尺度形成相对优势，再用于概率比率裁剪目标，配合参考策略 KL。原始设计不训练独立 value model；不同后续实现的归一化、长度处理与 KL 方式可能不同。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
同一道题里比较多份答卷，比把不同难度题的原始得分混在一起更有针对性。但如果这题的所有答案都错或都对且奖励相同，组内比较本身就没有方向。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
组的单位是同一个 prompt，不能把不同问题的奖励混合标准化。标准差的总体或样本约定、ε 处理与组大小都会改变数值；记录这些细节，才能解释优势尺度和复现梯度。

所有奖励相同时，中心化优势为零；分母加 ε 只能避免除零，不能创造区分信号。极小方差会放大微小评分噪声，稀疏奖励还可能导致大量全错组没有有效改进方向。

组内标准化可能抹去不同题目的绝对收益尺度，并影响任务加权。省掉 value model 也不等于整体计算必然更低，因为每个 prompt 需多次生成和评分；实际 token 成本应独立计算。
:::

### 有区分奖励与全相同奖励的组优势
:::

:::field{path="numericalExample.given" type="list"}
- 同 prompt 第一组奖励为 [1,0,1,0]，第二组均为 1。

:::field{path="numericalExample.steps" type="ordered"}
1. 第一组均值 0.5、标准差 0.5，优势近似 [1,−1,1,−1]。
2. 第二组均值 1、标准差 0，中心化奖励全为 0。
3. ε 防止除零，第二组优势仍全部为 0。
:::

:::field{path="numericalExample.result" type="text"}
一组产生正负方向，等分组没有组内优势信号；示例只核对归一化，不实现完整 GRPO。
:::

:::field{path="numericalExample.comparison" type="list"}
- 相对优势来自同问题回答之间的差异。
- 完整优化还需要旧概率、裁剪、参考策略与正确 token/序列约定。
:::


## 计算与实现步骤 {#algorithm-steps}

:::field{path="algorithmSteps" type="ordered"}
1. 对每个 prompt 从 old policy 采样 G 个输出
2. 奖励模型或规则评分
3. 组内标准化得到 advantage
4. 计算新旧策略 ratio
5. clipped surrogate
6. 加入 KL 约束并更新
7. 重新采样新组
:::

:::field{path="codeExamples.0.purpose" type="text"}
一组产生正负方向，等分组没有组内优势信号；示例只核对归一化，不实现完整 GRPO。

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
import math
groups = [[1.0, 0.0, 1.0, 0.0], [1.0, 1.0, 1.0, 1.0]]
for rewards in groups:
    average = sum(rewards) / len(rewards)
    std = math.sqrt(sum((r-average)**2 for r in rewards) / len(rewards))
    advantage = [(r-average)/(std+1e-8) for r in rewards]
    print(f"mean={average:.3f} std={std:.3f} advantages=" + ",".join(f"{a:.3f}" for a in advantage))
```
:::

:::field{path="codeExamples.0.explanation" type="list"}
- 第一组均值 0.5、标准差 0.5，优势近似 [1,−1,1,−1]。
- 第二组均值 1、标准差 0，中心化奖励全为 0。
- ε 防止除零，第二组优势仍全部为 0。
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 跨 prompt 混合奖励后仍称组相对优势。
- 零方差时除零，或把 ε 误当能产生新学习信号。
- 用新旧策略差的平方冒充完整参考策略 KL。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 跨 prompt 混合奖励后仍称组相对优势。
- 零方差时除零，或把 ε 误当能产生新学习信号。
- 用新旧策略差的平方冒充完整参考策略 KL。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### GRPO 不要 critic 就不需要奖励了吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
单个环境连续产生高度相关轨迹，等待长 episode 也会降低训练吞吐。并行运行多个环境能增加经验多样性；但收集并行与参数更新并行是不同设计，不能只看 worker 数量判断是哪一种。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
A3C 的多个 worker 用各自参数副本采样、计算梯度并异步更新共享参数；A2C 通常同步收集多个环境 rollout，聚合成批次后统一更新。两者常使用 n-step 回报和状态价值基线，属于典型 on-policy actor-critic 路线。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
A2C 像大家等一轮练习结束后共同修改笔记；A3C 像每个人随时提交修改，吞吐可能更灵活，但提交时依据的旧笔记可能已经过时。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
每段 rollout 的末尾若非真正终止，就用 critic 的末端价值补足未来；若终止则用零。多环境批次中各样本结束时间不同，必须保留逐样本边界，不能用一个全局 done 掩码覆盖所有环境。

同步聚合时损失通常按实际有效时间步求平均，而不是对不同长度 worker 的均值再无条件等权平均。两种平均对应不同样本权重，影响梯度尺度。

异步梯度来自较旧策略，存在参数陈旧与执行顺序随机性；同步实现更容易复现，但环境速度不均可能导致等待。并行吞吐收益不等于每次交互的样本效率提高，应分别报告。
:::

::::formula{index="0"}
:::field{path="formulas.0.label" type="text"}
### n-step critic 目标
:::

:::field{path="formulas.0.expression" type="math"}
$$
\hat G_t=\sum_{k=0}^{n-1}\gamma^k r_{t+k+1}+\gamma^n V(s_{t+n})
$$
:::

:::field{path="formulas.0.description" type="text"}
若片段内真正终止，终止后奖励与 bootstrap 为零。
:::

### 不同 worker 长度下的样本加权平均
:::

:::field{path="numericalExample.given" type="list"}
- worker A 有 2 个有效样本，每个损失为 1。
- worker B 有 1 个有效样本，损失为 4。

:::field{path="numericalExample.steps" type="ordered"}

:::

:::field{path="numericalExample.result" type="text"}

:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
worker_losses = [[1.0, 1.0], [4.0]]
sample_mean = sum(sum(x) for x in worker_losses) / sum(len(x) for x in worker_losses)
worker_mean = sum(sum(x) / len(x) for x in worker_losses) / len(worker_losses)
print(f"sample_mean={sample_mean:.3f}, worker_mean={worker_mean:.3f}")
```
:::

- 先算 worker 均值再等权平均为 (1+4)/2=2.5。
- 两者差异来自权重，不来自同步本身。

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 把任何多环境采样都叫 A3C。
- 混合长短 rollout 时无意改变每样本权重。
- 非终止 rollout 末端未 bootstrap，系统性低估价值。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 把任何多环境采样都叫 A3C。
- 混合长短 rollout 时无意改变每样本权重。

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### A2C 一定比 A3C 慢吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
不一定。硬件批处理、环境开销、等待与参数通信共同决定吞吐；同步还可能带来更易复现与更高批计算效率。
:::

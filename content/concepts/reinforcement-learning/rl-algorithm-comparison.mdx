## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
问“PPO 和 CQL 哪个更好”往往漏掉了前提：前者通常持续采样近期策略，后者针对固定 transition。若只有偏好对而没有奖励转移记录，问题又转到 DPO 一类目标；算法名称不能代替数据契约。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
算法比较首先对齐任务和可用证据，再分析价值或策略路线、on/off-policy、模型使用、动作空间与资源成本。单一排名无法覆盖在线控制、固定日志和语言偏好优化等不同问题；候选列表只是研究起点。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
选择车辆先看路面、载重和能否补能，再比较速度。同一把尺子比较不同前提下的成绩，可能把根本无法使用的工具排在最前。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
小型已知模型可先用 DP 建基准；小型未知离散环境可用表格 Q-learning 或 SARSA 检查任务。高维离散动作可考虑 DQN 家族，连续在线控制可比较 PPO、SAC、TD3 等，但仍需检查约束与假设。

固定 transition 要先处理覆盖与外推，CQL 与 IQL 是不同保守取舍；只有状态动作示范时行为克隆是直接基线。只有偏好对时，DPO 的离线偏好目标不能当作普通 MDP 算法的无缝替代。

筛选后应在相同交互量、评测协议和调参成本下比较。高最终回报、快墙钟时间、低约束违规和少环境试验可能互相冲突，结论必须绑定具体预算与失败分布。
:::

```Python
def candidates(data_contract):
    choices = {
        "fixed_transitions": ["CQL", "IQL"],
        "online_continuous": ["PPO", "SAC", "TD3"],
        "preference_pairs": ["DPO"],
    }
    return choices[data_contract]
for contract in ["fixed_transitions", "online_continuous", "preference_pairs"]:
    print(contract + ": " + ", ".join(candidates(contract)))
```

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 忽略数据类型与交互许可，直接按算法流行度选择。
- 把 on/off-policy 与 online/offline 当成同一分类。
- 用不同预算或挑选过的最好运行排算法名次。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 有覆盖所有场景的最好算法吗？
:::

:::field{path="commonQuestions.0.answer" type="text"}
没有脱离任务和预算的统一结论。先排除违反数据接口或交互边界的方法，再用基线和固定评测协议比较候选。
:::

## 背景与问题 {#background}

:::field{path="background" type="paragraphs"}
两辆仓库机器人同时选路线，会相互改变碰撞和拥堵；一辆机器人先选“去充电”再执行多步控制，则是在不同时间尺度上决策。多智能体与分层可以同时存在，但它们带来的建模困难不同。
:::


## 概念定义 {#definition}

:::field{path="definition" type="paragraphs"}
多智能体强化学习研究多个策略共同影响环境与收益的情形，可协作、竞争或混合。分层强化学习用技能、子目标或 option 表达时间延展动作。option 通常包含启动条件、内部策略与终止规则，不能仅当作一个动作别名。
:::


## 直观理解 {#intuition}

:::field{path="intuition" type="paragraphs"}
多智能体像多人配合搬家，需要考虑队友会怎样行动；分层像先决定“打包厨房”，再执行一串细动作，重点是把长任务分成有持续时间的技能。
:::


## 核心原理 {#core-principle}

:::field{path="corePrinciple" type="paragraphs"}
其他学习者不断改策略，会使单个智能体看到的转移与回报分布变化。独立 replay 的旧经验可能对应旧队友；集中训练分散执行可在训练期用更多信息，但执行策略不能偷偷依赖不可获得的全局状态。

联合动作空间随智能体数量乘法增长，团队奖励还会带来个体信用分配。集中 critic、值分解或通信协议各有结构假设，不能因为协作就声称所有贡献可自动辨别。

技能持续 k 步时，高层备份需要累计这 k 步奖励并用 γ 的 k 次幂折扣后继价值。忽略持续时间会错误比较长短技能；技能可中断性与安全终止也需显式定义。
:::

::::formula{index="0"}

### 持续 k 步的高层备份
:::

:::field{path="formulas.0.expression" type="math"}
$$
y=\sum_{j=0}^{k-1}\gamma^j r_{t+j+1}+\gamma^k V(s_{t+k})
$$
:::

:::field{path="formulas.0.description" type="text"}
option 终止与任务真正终止不同；后者将高层后继项置零。
:::

### 持续两步的 option 如何备份
:::

:::field{path="numericalExample.given" type="list"}
- 技能产生奖励 1、2，持续 2 步，之后高层价值为 4。
- 折扣 0.9，技能结束不是任务终止。
:::

:::field{path="numericalExample.steps" type="ordered"}
1. 技能内折扣回报为 1+0.9×2=2.8。
2. 高层后继项为 0.9²×4=3.24。
3. option 目标为 6.04；不能误写为 2.8+0.9×4。
:::

:::field{path="numericalExample.result" type="text"}
两步 option 目标为 6.040，持续时间决定后继折扣。
:::

:::field{path="numericalExample.comparison" type="list"}
- 时间抽象改变决策间隔，多智能体改变决策者数量。
- 本例只核对高层折扣，未实现多个学习者的交互。
:::

:::field{path="codeExamples.0.source" type="code" trailing="0"}
```Python
rewards, gamma, next_high_value = [1.0, 2.0], 0.9, 4.0
duration = len(rewards)
within_option = sum(gamma ** i * r for i, r in enumerate(rewards))
target = within_option + gamma ** duration * next_high_value
print(f"duration={duration}, option_target={target:.3f}")
```
:::

## 常见错误 {#pitfalls}

:::field{path="pitfalls" type="list"}
- 把多智能体与分层当作同一算法类别。
- 训练 critic 的全局信息泄露给部署 actor。
- 高层技能持续多步却只用一次 γ 折扣后继。
:::

## 失败模式、风险与性能 {#failure-performance}

:::field{path="failureModes" type="list"}
- 把多智能体与分层当作同一算法类别。
- 训练 critic 的全局信息泄露给部署 actor。
- 高层技能持续多步却只用一次 γ 折扣后继。
:::

:::field{path="securityRisks" type="list"}
- 奖励函数与真实目标不一致会诱发奖励黑客。
- 部署策略的行动权限必须由环境和应用层约束。
:::

:::field{path="performanceNotes" type="list"}
- 样本效率、墙钟时间和显存占用需要分别报告。
- 应使用多个随机种子、置信区间和固定评测策略。
:::


## 常见问题 {#common-questions}

:::field{path="commonQuestions.0.question" type="text"}
### 集中训练是否允许执行时读取所有状态？
:::

:::field{path="commonQuestions.0.answer" type="text"}
只有部署确实能获得这些信息才可以。集中训练分散执行的核心正是让部署 actor 仅依赖本地可用信息。
:::

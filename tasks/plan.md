# Implementation Plan: 渐进学习路线 V2

## Overview

重构知识路线法和深度理解法，让概念严格沿有效前置关系逐步推进，并把每个概念压缩为两张主任务卡。定义内容改成约 120～180 个中文字符的自然段介绍，不使用“定义：用途：边界：”式分项，也不生成一句话记忆点。任务时间由内部子步骤直接求和，同时修复每周时间输入和非法日期输入。

继续保持本地运行和 localStorage 持久化，不增加远程 API、登录或部署。

## Confirmed Decisions

- 严格逐概念推进。
- 每个概念两张主任务卡。
- 定义目标 120～180 字，使用连续自然段。
- 不显示字段标签，不使用冒号分隔，不生成一句话记忆点。
- 日期使用年、月、日三个选择框，日选项随年月变化。
- 同时实施内容增强与时间重新计算。

## Architecture Decisions

### 1. 严格前置顺序

- 把标题、别名、ID 和 slug 统一解析为有效概念 slug。
- 为目标概念计算完整前置闭包，必要时加入跨方向桥接概念。
- 使用稳定拓扑排序；收藏只影响同层顺序，难度不再重新打乱结果。
- 循环、缺失和不可访问依赖生成警告，不生成无效链接。

### 2. 两张任务卡

“名词与理解”卡包含自然段定义、问题背景、核心直觉、前后关系和简短理解检查。

“原理与实践”卡包含核心原理、公式或最小例子、存在时的代码或交互实验、自我解释及理解问题。

主列表只显示两张卡，子步骤可展开并独立完成。已完成阶段默认折叠，页面顶部显示下一条建议任务。

### 3. 定义自然段

从现有 definition、summary、corePrinciple、prerequisites、relatedConcepts 和 inputs/outputs 中提取内容，自然连接成一小段文字。来源不足时宁可短一些，也不使用空洞句子凑字数；超长时按完整句子裁剪。段落需要让学习者理解名词是什么、解决什么问题、研究对象是什么以及后续用于哪里，但页面不显示这些字段名称。

### 4. 统一时间来源

删除独立 perConcept 估算。任务卡时间等于子步骤分钟数总和，计划容量和预计完成日期使用同一结果。

| 子步骤 | 时间 |
| --- | ---: |
| 阅读自然段定义 | 5 分钟 |
| 理解用途、边界和知识位置 | 3 分钟 |
| 理解直觉 | 3～5 分钟 |
| 核心原理 | 5～8 分钟 |
| 公式或最小例子 | 5～10 分钟 |
| 代码阅读 | 8～12 分钟 |
| 交互实验 | 10～15 分钟 |
| 自我解释 | 3～5 分钟 |
| 理解检查 | 5 分钟 |
| 聚合复习 | 5～8 分钟 |

### 5. 聚合复习

知识路线法和深度理解法不再为每个概念分别生成 1、3、7、14 天四条主任务，而是每阶段生成聚合复习卡。间隔复习法保留原节奏，但以概念组展示。

### 6. 输入修复

- 每周时间在输入过程中保存字符串，允许暂时为空。
- 失焦或生成时再解析，有效范围 30～10080 分钟。
- 非法值显示行内错误，不自动变成 0。
- 增加 120、300、480、600 分钟快捷值。
- 日期使用年月日选择框，日列表根据月份和闰年生成。
- 生成前校验日期存在且不早于开始日期。

## Dependency Graph

测试契约 → 前置规范化与拓扑路线 → 定义段落与子步骤模型 → 两种方法 V2 与时间计算 → 任务卡和下一步界面 → 时间与日期输入 → 旧计划迁移与完整验证。

## Task List

### Phase 1: Logic Foundation

1. 添加渐进路线、定义段落、任务压缩、时间求和和输入校验失败测试。
2. 规范化前置关系并生成严格拓扑路线。
3. 增加任务子步骤、定义自然段和旧数据迁移默认值。

### Phase 2: Route Generation

4. 重写知识路线法为每概念两张卡。
5. 重写深度理解法为每概念两张卡。
6. 统一分钟计算、容量选择和阶段聚合复习。

### Phase 3: Interaction

7. 更新预览和详情页，显示自然段定义及可展开子步骤。
8. 增加下一条建议任务、完成阶段折叠和未完成过滤。
9. 修复每周时间输入并增加快捷值。
10. 用年月日选择框替换当前日期输入。

### Phase 4: Compatibility and Verification

11. 迁移旧计划并回归学习、收藏、重点和备忘录联动。
12. 运行测试、定向 lint、TypeScript、本地构建和路由验证。

## Risks and Mitigations

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| prerequisites 同时含标题、别名和 slug | 高 | 统一使用现有概念解析器并测试跨方向依赖 |
| 定义自然段出现重复句 | 中 | 规范化去重并按完整句子裁剪 |
| 旧任务已有完成记录 | 高 | 保留原任务 ID、状态和完成时间 |
| 两张卡仍包含过多信息 | 中 | 默认折叠子步骤，只显示进度与下一步 |
| 日期受时区影响 | 中 | 使用本地年月日，不经过 UTC 转换 |
| 时间再次双重计算 | 高 | 只允许从子步骤求和，并用测试锁定 |

## Not Doing

- 不增加一句话记忆点。
- 不调用远程模型扩写定义。
- 不把定义改成带标签的字段列表。
- 不增加云端同步、登录或部署。

## Acceptance Criteria

- 两种路线都严格遵守前置关系，每个概念最多两张主卡。
- 定义为自然段，目标 120～180 字，不使用标签式冒号分隔。
- 阅读定义为 5 分钟，其他时间从子步骤统一求和。
- 普通路线不再生成上百条平铺任务。
- 每周时间输入可以先删空再输入。
- 日期控件不能选择不存在的日期。
- 旧计划及学习、收藏、重点和备忘录状态不丢失。
- 本地测试、类型检查和构建成功。

## Open Questions

无。已采用推荐方案，并按用户补充取消一句话记忆点和标签式定义展示。
